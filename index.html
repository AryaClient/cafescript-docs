CafeScript は、Wii U（PowerPC 750 系 32 ビット、ビッグエンディアン）上で動作中のプログラムに読み込まれ、その場でコンパイルされる小規模な言語です。

CafeScript とは

主な用途は次のとおりです。

  • 既存プロセスのメモリレイアウトを記述し、読み書きする
  • 既存プロセスの関数を呼び出す、またはフックする
  • ホスト（埋め込み側）に関数とデータを提供する

対象プロセスのクラスやフィールドを struct と extern fn で宣言しておけば、あとは普通のプログラムと同じように書けます。ポインタは明示的に参照外しし、null になりうる値は ?*T 型で表します。

設計方針

  • 1 つのことには 1 つの書き方。同じ意味の構文を複数用意しない。
  • 暗黙を最小にする。暗黙の型変換は限られたものだけ。条件式は bool に限る。ポインタは自動で参照外ししない。
  • 書き込み先が字面で分かる。代入先が -> か .* を通れば、ポインタの指す先のメモリへの書き込みである。
  • null の可能性を型で表す（?*T と *T）。
  • 宣言の順序に依存しない。ファイルの意味は、そのファイル自身と、それが直接 import したものだけで決まる。
  • 外部の事実は extern 宣言の 1 か所だけで導入する。hook や呼び出しはそれを名前で参照する。

はじめてのスクリプト

対象プロセスの構造体と関数を宣言し、そこに読み書きする例です。

#[size(0x0C)]
struct Vec3 {
    x: f32;
    y: f32;
    z: f32;
}

struct Actor {
    mPos: Vec3 at 0x10;
    mSpeed: f32 at 0x1C;

    extern fn GetActor(index: u32) -> ?*Actor at 0x02000000;
}

fn speedUp(step: f32) {
    for i in 0..8 {
        let actor = Actor::GetActor(i) orelse continue;
        actor->mSpeed += step;
    }
}
  • at OFFSET を書いたフィールドは、そのオフセットのメモリを直接読み書きします。
  • extern fn ... at ADDR は、そのアドレスの関数を呼び出します。
  • -> はポインタの参照外しです。?*T は orelse などで *T に取り出してから使います。

0. 概要と設計方針

CafeScript は、Wii U（PowerPC 750 系 32 ビット、ビッグエンディアン）上で動作中のプログラムに読み込まれ、その場でコンパイルされる小規模なコンパイル言語である。主な用途は次のとおり。

  • 既存プロセスのメモリレイアウトを記述し、読み書きする
  • 既存プロセスの関数を呼び出す、またはフックする
  • ホスト（埋め込み側）に関数とデータを提供する

設計方針

  1. 1 つのことには 1 つの書き方。同じ意味の構文を複数用意しない。
  2. 暗黙を最小にする。暗黙の型変換は 14.1 節のものだけ。条件式は bool に限る。ポインタは自動で参照外ししない。
  3. 書き込み先が字面で分かる。代入先が -> か .* を通れば、ポインタの指す先のメモリへの書き込みである（13.4 節）。
  4. null の可能性を型で表す（?*T と *T）。ただし実行時の表現は C のポインタと同じで、最適化の前提には使わない。
  5. 宣言の順序に依存しない。ファイルの意味は、そのファイル自身とそのファイルが直接 import したものだけで決まる。
  6. 外部の事実は extern 宣言の 1 か所だけで導入する。アドレスとシグネチャを書くのは extern 宣言だけで、hook や呼び出しはそれを名前で参照する。

1. 字句構造

1.1 ソース

  • ソースファイルは UTF-8 で書く。BOM があれば無視する。
  • 改行は LF または CRLF。改行は空白の一種として扱い、文法上の意味は持たない。
  • ファイル拡張子は .cafe。

1.2 コメント

// 行末までのコメント
/* ブロックコメント。/* 入れ子にできる */ */

1.3 識別子

identifier = (letter | "_") { letter | digit | "_" }
letter     = "A".."Z" | "a".."z"
digit      = "0".."9"
  • 識別子に使えるのは ASCII 文字だけ（非 ASCII 文字は文字列とコメントの中でのみ使える）。
  • 大文字と小文字は区別する。
  • _ 単独は識別子ではなく、ワイルドカードを表す記号として予約する（12.10 節）。

1.4 キーワード

次の語は予約語であり、識別子として使えない。

as        at        break     const     continue  defer     delete    else
enum      export    extern    false     fn        for       from      hook
if        import    in        interface let       loop      match     namespace
new       null      orelse    original  priv      return    self      Self
struct    true      type      use       var       void      while

型名（i32 など）はキーワードではない。プレリュードで定義された名前として扱う（4.1 節）。

1.5 整数リテラル

123        1_000_000
0x1100_0000   0X1F
0b1010_0101
0o755
  • _ は区切りとして数字の間に置ける（先頭・末尾・接頭辞の直後には置けない）。
  • 符号は含まない。-1 は単項マイナスとリテラルの組である。
  • 整数リテラルは型なし整数定数であり、型は文脈で決まる（13.2 節）。

1.6 浮動小数点リテラル

1.0    0.5    3.14159    1.0e-3    6.02E23    1_000.5
  • 小数点の前後に、少なくとも 1 桁ずつ数字が必要（1. と .5 は不可）。
  • 型を示す接尾辞はない。型なし浮動小数点定数として、型は文脈で決まる（13.2 節）。

1.7 文字リテラル

'a'    '\n'    '\x41'
  • 1 バイトで表せる ASCII 文字だけを書ける。型なし整数定数として扱う（値は文字コード）。

1.8 文字列リテラル

"hello"          // 型: const *u8（cstr。UTF-8、末尾 NUL）
u"こんにちは"    // 型: const *u16（wstr。UTF-16 BE、末尾 NUL）
  • "..." の内容は UTF-8 のバイト列として、末尾に 0 を 1 つ付けて配置される。
  • u"..." の内容は UTF-16（ビッグエンディアン、サロゲートペア可）として、末尾に 0 を 1 つ付けて配置される。
  • 文字列リテラルの値は、読み取り専用データ領域に置かれた先頭要素のアドレスであり、null にはならない。
  • 内容が同じリテラルは、1 回のコンパイルの中で同じアドレスにまとめてよい。
  • リテラルは const のポインタ（4.2 節）なので、それを通して書き込めない。as で const を外して書き込んだ場合の動作は未定義（18 節）。

2. プログラム構造

2.1 コンパイル単位

  • 1 回のコンパイルの対象は、エントリファイルと、そこから import で推移的に到達するファイルの集合である。これをコンパイル単位と呼ぶ。
  • ホストでは、スクリプト 1 本が 1 つのコンパイル単位である。異なるコンパイル単位の名前は互いに干渉しない。

2.2 ファイルの構成

ファイルは、次のトップレベル要素の並びからなる。

  • import 宣言
  • use 宣言
  • namespace ブロック
  • 宣言: struct, enum, type, fn, extern fn, const, var, let
  • hook 宣言（エントリファイルのみ）
  • 上記の一部に付ける修飾子: export（エントリファイルのみ）、priv

トップレベルの要素は、ファイルの中でどの順序に書いてもよい。

2.3 import

import "mc/client/Minecraft.cafe";
  • import は、指定したファイルをコンパイル単位に加え、そのファイルの宣言をこの import を書いたファイルから参照できるようにする。
  • パスは次の順で探し、最初に存在したものを使う。
    1. import を書いたファイルのディレクトリからの相対パス
    2. ホストまたはコマンドラインで指定されたライブラリルート（指定された順）
  • 親ディレクトリを遡って探すことはしない。
  • 区切り文字は /。.. を含むパスも書ける。
  • 同じファイル（正規化したパスが同じもの）を何度 import しても、コンパイル単位には 1 回だけ加わる。
  • import は循環してよい。
  • import は推移しない。A が B を import し、B が C を import していても、A から C の宣言は名前で参照できない（型を経由した利用は可。3.6 節）。
  • import は名前を導入しない。名前の短縮には use を使う。

2.4 namespace

namespace mc {
    struct Vec3 { ... }
}

namespace mc::entity {
    struct Entity { ... }
}
  • namespace は名前の所属を決めるだけで、実体を持たない。
  • 同じ名前空間を、複数のファイル、または同じファイル内の複数のブロックで開いてよい。
  • namespace a::b { } は namespace a { namespace b { } } と同じ意味である。
  • 名前空間の中には、import, use, hook, export 以外のトップレベル宣言を書ける。import, use, hook, export はファイルのトップレベル（名前空間の外）にだけ書ける。
  • 名前空間に属さない宣言は、グローバル名前空間に属する。

2.5 use

use mc::Minecraft;            // Minecraft を mc::Minecraft の短縮名にする
use mc::entity as ent;        // ent を mc::entity の短縮名にする
use mc::Vec3::ThreadStorage;  // 入れ子の型も可
  • use P; は、パス P の最後の要素の名前を、P が指すものの短縮名として導入する。
  • use P as N; は、N を P の短縮名として導入する。
  • P は名前空間・型・関数・定数・変数のいずれかを指してよい。
  • 短縮名が有効なのは、use を書いたファイルの中だけである。
  • * でまとめて導入する書き方はない。
  • use の対象は、そのファイルから参照できる宣言でなければならない（3.4 節）。

2.6 宣言の順序

  • トップレベル宣言は、宣言より前の位置から参照してよい。前方宣言は存在しない。
  • 定数の初期化式と構造体のレイアウトが循環した場合はエラーとする（例: const A = B; const B = A;、struct S { s: S; }）。ポインタを介した自己参照（struct Node { next: ?*Node; }）は循環ではない。

2.7 export

export fn CreateModule() -> ?*Module { ... }
export const VERSION: u32 = 1;
export var gState: u32 = 0;
  • export は、宣言をホストから名前で探せる記号として出力する。
  • 書けるのはエントリファイルのトップレベル（名前空間の外）の fn, const, var だけである。
  • export された名前は、ホスト側から見た記号名と同じになる。
  • export const は、その値を保持するデータ記号として出力される。
  • export されていない宣言は、ホストから見えない。使われていなければ削除してよく、インライン化してもよい。

2.8 priv

priv const SECRET: u32 = 42;

struct Timer {
    priv elapsed: u32;
    fn tick(self) { ... }
}
  • priv を付けた宣言、またはフィールドやメソッドは、それを宣言したファイルの中からだけ参照できる。
  • priv は型単位ではなく、ファイル単位の可視性である。
  • priv を付けない宣言は、そのファイルを import したファイルから参照できる。

3.1 名前の種類

1 つのスコープの中で、名前は次のいずれか 1 つを指す。

  • 名前空間
  • 型（構造体、列挙型、型別名、ジェネリック型の型引数）
  • 関数（fn、extern fn）
  • 定数（const）
  • 変数（var、let、引数）
  • 列挙型のメンバ

型の名前と値の名前に、別々の名前空間は設けない。1 つのスコープで 1 つの名前は 1 つのものだけを指す。

3.2 正式名

名前空間・型・関数・定数・グローバル変数は、正式名（グローバル名前空間からのパス、例: mc::Vec3::ThreadStorage）で識別される。

  • コンパイル単位の中で、同じ正式名の宣言が 2 つあればエラーである。ただし名前空間どうしは除く（名前空間は再度開ける）。
  • 同じ正式名で、名前空間とそれ以外（例: 名前空間 mc::Vec3 と構造体 mc::Vec3）を作るとエラーである。

3.3 スコープ

内側から順に、次のスコープがある。

  1. ブロック（関数本体、if / while / for / loop / match の各ブロック、単独のブロック）
  2. 関数の引数（と self）
  3. 囲んでいる構造体の関連スコープ（関連する型、定数、関数、ジェネリック型の型引数、Self）。構造体の中に書かれた関数本体からのみ有効
  4. ファイルの use による短縮名
  5. 囲んでいる名前空間（内側から外側へ順に）
  6. グローバル名前空間
  7. プレリュード

構造体のフィールドは、どのスコープにも入らない。フィールドには、必ず self->x のように受け手を明示してアクセスする。

3.4 参照できる宣言

ファイル F から修飾付きまたは修飾なしで参照できる宣言は、次のいずれかである。

  • F 自身に書かれた宣言
  • F が直接 import したファイルに書かれた、priv でない宣言
  • プレリュードの宣言

これらの宣言が属する名前空間を、F から参照できる名前空間とする。

3.5 修飾なしの名前の探索

修飾なしの名前 N は、3.3 節のスコープを内側から順に調べる。

  • スコープ 1〜3 では、最初に見つかったものを使う。
  • スコープ 4 では、use による短縮名を調べる。
  • スコープ 5〜7 では、各名前空間の中で N を宣言しているもののうち、3.4 節の条件を満たすものを調べる。

見つからなければエラーである。

ローカル変数は、外側のスコープにある同じ名前（外側のブロックのローカル変数、グローバル宣言など）を隠してよい。同じブロックの中で同じ名前を 2 回宣言するとエラーである。引数と同じ名前を、関数本体の一番外側のブロックで宣言するのもエラーである。

3.6 修飾付きの名前

A::B::C は、先頭の A を 3.5 節に従って解決し、その後は各要素の中で順に名前を探す。:: の右側に書けるのは次のものである。

左側右側に書けるもの
名前空間その名前空間の宣言（3.4 節の条件を満たすもの）
構造体関連する型、関連する定数、関数（self のある関数も含む。8.6 節）。関数は基底（祖先を含む）のものも探す
列挙型メンバ

::A のように先頭に :: を書くと、グローバル名前空間から探す。

型を経由した利用: 式の型が持つフィールドやメソッドを -> や . で使う場合は、その型の宣言を含むファイルを import している必要はない。名前で書く場合（型注釈、as、構造体リテラル、Type::f()、hook など）だけ、3.4 節の条件が必要になる。

  • *T と ?*T の実行時の表現は同じで、null は値 0 である。
  • ? は直後の * 1 つだけに付く。?*?*T は「null かもしれない、『null かもしれない T へのポインタ』へのポインタ」である。
  • *void は参照外し、メンバアクセス、ポインタ演算、添字ができない。
  • T には任意の型を書ける（基本型、構造体、列挙型、配列、ポインタ、関数型）。

const

fn length(v: const *Vec3) -> f64 {
    return v->x * v->x + v->y * v->y;    // 読むのはよい
    // v->x = 0.0;                       // エラー: 書き込めない場所
}

let n: u32 = 3;
let p = &n;                              // p: const *u32
  • const *T と const ?*T は、指す先に書き込めないポインタ（const ポインタ）である。*T / ?*T とは別の型だが、表現は同じ。スライス（const []T、4.3 節）とインターフェースへのポインタ（const *I / const ?*I、5.9 節）にも書ける。それ以外の型の前に const を書くとエラー。
  • const ポインタを通った場所（p->f、p.*、p[i]）は書き込み可能でない（13.4 節）。そのアドレス（&p->f）も const ポインタになる（13.13 節）。
  • const が及ぶのは、指す先の 1 段だけである。p: const *S から読んだフィールド q: *T は *T のままで、その先には書き込める（C の const と同じ）。
  • *T から const *T には暗黙に変換できる。逆向きの暗黙の変換はない（14.1 節）。as では外せる（14.2 節）が、外したポインタを通して、書き込み可能でない場所（let の変数、引数、文字列リテラル）に書き込んだ場合の動作は未定義（18 節）。
  • const ポインタは delete できない（12.13 節）。
  • const ポインタを通して呼べるメソッドは、const self を取るものだけである（8.5 節）。

4.3 配列型

[16]u8
[4][4]f32      // 4 要素の配列（各要素は [4]f32）
  • [N]T は、T を N 個並べた値型である。N は 0 以上の定数式（16 節）で、型は整数。
  • サイズは N * @sizeof(T)、アラインメントは @alignof(T)。
  • 配列は値であり、代入するとコピーされる。
  • a.len は要素数 N を表す型なし整数定数である。

スライス型

[]u32
[]shared_ptr<Entity>
  • []T は、「先頭の要素へのポインタ」と「要素数」の組である（スライス）。値型で、サイズ 8、アラインメント 4。レイアウトは ptr: ?*T at 0x0; len: u32 at 0x4; と同じ。
  • スライスは要素を所有しない。指している要素の寿命はプログラマの責任である。
  • s.len（u32）と s.ptr（?*T）で中身を読める。どちらも書き込めない。新しい範囲が欲しいときは p[from..to]（13.6 節）で作り直す。
  • null は空のスライス（ptr が null、len が 0）に暗黙に変換できる。ゼロ値も空のスライスである。
  • const []T は、要素に書き込めないスライスである。s[i] は書き込み可能でなく、s.ptr は const ?*T、s[i..j] も const []T になる。[]T から const []T には暗黙に変換できる（14.1 節）。書き込めない場所や const ポインタから作ったスライスは const []T になる（13.6 節）。
  • 要素数が 0 のスライスでは、ptr は null でもよい。要素数が 1 以上なら、ptr は null であってはならない。
  • スライスどうしは比較できない（s.len == 0 で空かどうかを調べる）。

4.4 関数型

fn(i32, f32) -> bool
fn(*Entity)          // 戻り値なし
?fn(*Entity)         // null かもしれない関数ポインタ
  • 関数型の値は、関数のアドレスである。サイズ・アラインメントは 4。
  • fn(...) は null にならない。null かもしれない関数ポインタは ?fn(...) と書く。
  • 関数型に可変長引数（...）は書けない。可変長引数は extern 宣言だけで使える（9.4 節）。
  • 2 つの関数型は、引数の型の並びと戻り値の型がすべて同じなら同じ型である。

4.5 構造体型・列挙型・インターフェース

5 節と 6 節、5.9 節を参照。

4.6 型別名

type TickFn = fn(*Entity);
type EntityList = [64]?*Entity;
  • type N = T; は、N を T の別名にする。新しい型は作らない（N と T は同じ型）。
  • 別名を循環させるとエラーである。
  • 型別名はジェネリック引数を取れない。

4.7 プレリュード

すべてのファイルは、次の宣言を参照できる（グローバル名前空間より外側のスコープ）。

// 基本型: i8 i16 i32 i64 u8 u16 u32 u64 f32 f64 bool
type cstr = const *u8;
type wstr = const *u16;

プレリュードと同じ名前をグローバル名前空間で宣言するとエラーである。

4.8 戻り値のない関数

戻り値のない関数は、戻り値の型を書かない。void は単独では型ではなく、*void と ?*void の中でのみ使える。

4.9 型の同一性

  • 基本型は名前で同一。
  • 構造体と列挙型は正式名で同一（ジェネリック構造体は、正式名と型引数の組で同一）。
  • ポインタ型・配列型・関数型は構造で同一。
  • 型別名は、別名を展開した型で同一。

5. 構造体

5.1 宣言

struct Vec3 {
    x: f64;
    y: f64;
    z: f64;
}

#[size(0x58)]
struct Minecraft {
    mThePlayer: SharedPtr<MultiplayerLocalPlayer> at 0x104;
    mLevel: ?*MultiplayerLevel at 0x108;

    extern fn GetInstance() -> ?*Minecraft at 0x02001000;
}

構造体の本体には、次のものを書ける。

  • フィールド: [priv] name: Type [at OFFSET];
  • 関数: fn、extern fn（8 節、9 節）
  • 関連する型: struct, enum, interface, type
  • 関連する定数: const

5.2 レイアウト

フィールドは、宣言順に次のように配置する。

  1. at OFFSET があれば、オフセットは OFFSET（定数式）である。OFFSET はそのフィールドのアラインメントの倍数でなければならない。
  2. at がなければ、直前のフィールドの末尾（オフセット + サイズ）を、そのフィールドのアラインメントの倍数に切り上げた位置に置く。最初のフィールドで、継承がなければ 0、継承があれば基底のサイズから始める。
  3. 2 つのフィールドの領域が重なる場合、少なくとも一方が at で明示されていなければならない。どちらも自動配置であれば、重なることはない。at で明示した重なりは別名として許す。

構造体のアラインメントは、全フィールド（基底を含む）のアラインメントの最大値である。フィールドがなければ 1。

構造体のサイズは、全フィールドの末尾の最大値を構造体のアラインメントの倍数に切り上げたものである。フィールドがなければ 0。

#[size(N)] を付けると、サイズを N にする。計算したサイズより N が小さい場合や、N がアラインメントの倍数でない場合はエラーである。

5.3 継承

struct LivingEntity : Entity {
    mHealth: f32 at 0x1F4;
}
  • 継承は単一継承だけ。基底は構造体でなければならない。: の後には、基底の構造体（あれば最初に 1 つ）と、実装するインターフェース（5.9 節）を , で区切って並べる。
  • 基底のフィールドは、派生構造体のオフセット 0 から基底と同じ配置で含まれる。
  • 派生側の at は、派生構造体の先頭からのオフセットである。基底のフィールドと領域が重なるとエラー。
  • 派生側で、基底（祖先を含む）と同じ名前のフィールドを宣言するとエラー。
  • 派生側で、基底と同じ名前の関数を宣言してよい。これは隠蔽であり、どちらが呼ばれるかは受け手の静的な型で決まる（8.6 節）。仮想呼び出しではない。
  • フィールドと関数で同じ名前を使うとエラー（基底由来のものも含む）。
  • *Derived は *Base に暗黙に変換される（14.1 節）。

5.4 フィールドの型

  • フィールドには、任意のサイズ確定済みの型を書ける。構造体を値として埋め込むことも、配列も、ポインタも可。
  • 構造体が自分自身を値として（直接または間接に）含むとエラー。

5.5 関連する宣言

struct Vec3 {
    struct ThreadStorage { ... }    // mc::Vec3::ThreadStorage
    enum Axis: i32 { X, Y, Z }      // Vec3::Axis::X
    const ZERO_LEN: f64 = 0.0;
    type Scalar = f64;
}
  • 関連する宣言は、構造体の正式名の下に属する。
  • 構造体の中に書いた関数本体からは、修飾なしで参照できる（3.3 節）。

5.6 値としての構造体

  • 構造体は値型である。代入、初期化、引数渡し、戻り値で丸ごとコピーされる。ただし、ドロップされる型（8.11 節）は、コピー関数を持つものだけコピーでき、その関数が呼ばれる。
  • 構造体どうしの == / != は定義されない（エラー）。
  • 構造体の値に -> は使えない。. を使う。

5.7 構造体リテラル

let v = Vec3 { x: 1.0, y: 0.0, z: 0.0 };
var t = RepeatTimer { elapsed: 0, interval: 20, count: 0 };   // 継承したフィールドも並べて書く
let z = Vec3 {};                                              // 全フィールド 0
  • Type { name: expr, ... }。最後の , は省略できる。
  • フィールドは任意の順で書けるが、同じフィールドを 2 回書くとエラー。
  • 省略したフィールドは、ゼロ値（15.5 節）になる。ゼロ値を持たない型（*T、fn(...)、それらを含む型）のフィールドは省略できない。
  • at で別名になっているフィールドのうち、指定できるのは 1 つだけ。別名どうしを両方指定するとエラー。
  • ジェネリック構造体は SharedPtr::<Player> { ... } と書く（7.3 節）。
  • if / while / match / for の見出し（{ の直前の式）に構造体リテラルを書く場合は、括弧で囲む。

5.8 配列リテラル

let a = [4]i32 { 1, 2, 3, 4 };
var buf = [16]u8 {};         // 全要素 0
  • [N]T { e0, e1, ... }。要素数が N より少なければ、残りはゼロ値になる（ゼロ値を持たない T では、要素を省略できない）。N より多いとエラー。

5.9 インターフェース

interface Module {
    fn init(self);
    fn onTick(self);
    fn onEnable(self) {}                     // 既定の本体
}

struct Counter : Module {
    ticks: u32;

    fn init(self) { self->ticks = 0; }
    fn onTick(self) { self->ticks += 1; }    // onEnable は既定の本体を使う
}

export fn CreateModule() -> ?*Module {
    return new Counter { ticks: 0 };         // ?*Counter → ?*Module
}

fn Tick(m: *Module) { m->onTick(); }         // Counter::onTick が呼ばれる
  • interface Name { fn name(self, ...) [-> T]; ... } は、関数の名前と型の組を宣言する。関数は self か const self（8.5 節）を最初の引数に取る。属性は付けられない。インターフェースはジェネリクスにできない。
  • 関数は本体（既定の本体）を持ってよい。実装する構造体がその名前のメソッドを持たないとき、既定の本体が使われる。既定の本体の中では、self は *I 型であり、インターフェースの関数を呼ぶことだけで構造体に触れる。Self は使えない。既定の本体は、それを使う構造体ごとに型検査し、コードを作る。
  • インターフェースは値の型ではない。値として使えるのは *I と ?*I（インターフェースへのポインタ）だけで、I 自体を変数・フィールド・配列の要素・引数の型に書くとエラー。
  • 構造体は、: の後に並べたインターフェースを実装する（struct S : Base, I1, I2）。並べたインターフェースの既定の本体のない関数ごとに、同じ名前のメソッドを持たなければならない（8.6 節の探索で、基底のものでもよい）。self の後の引数の型の並びと戻り値の型は、インターフェースのものと同じでなければならない。インターフェースの関数が const self なら、実装も const self でなければならない（self の関数は、どちらで実装してもよい）。extern 関数でもよいが、可変長引数の関数、ドロップ関数（8.11 節）、他のファイルの priv 関数は使えない。満たさなければ、構造体の宣言でエラー。
  • 実装は継承されない。*S を *I にできるのは、S 自身が I を並べた場合だけである。
  • *S / ?*S は、S が実装する *I / ?*I に暗黙に変換される（14.1 節）。逆向き（*I から *S）の変換はない。
  • p->m(args)（p: *I）は、p を作ったときの構造体のメソッドを呼ぶ（動的な呼び出し）。?*I は、?*T と同じく 15 節の方法で取り出してから呼ぶ。
  • const *I / const ?*I は、const self の関数だけを呼べるインターフェースへのポインタである。*S / const *S から作れ、*I から暗黙に変換できる（逆はできない。as でも外せない）。const self の関数の既定の本体の中では、self は const *I 型である。
  • *I / ?*I で使えるのは、インターフェースの関数の呼び出し、代入・初期化・引数・戻り値・フィールドへの格納、null との比較（?*I のみ）、orelse、if let、while let、後置 ?、delete（12.13 節）だけである。.*、フィールドアクセス、添字、ポインタ演算、as によるほかの型への変換、*I どうしの比較はできない。
  • 表現: *I は 2 ワード（サイズ 8、アラインメント 4）で、オフセット 0 に構造体へのポインタ、オフセット 4 に関数表へのポインタを持つ。関数表は、インターフェースで宣言した順に関数のアドレスを並べ、最後に削除関数を加えた配列で、構造体とインターフェースの組ごとに 1 つ作られる。削除関数は、その構造体へのポインタを delete するのと同じこと（12.13 節）をする。表の関数は、オフセット 0 のポインタを self として呼ぶ。?*I が null のときは、オフセット 0 が 0 である（オフセット 4 の値は未規定）。引数と戻り値では、構造体の値と同じく扱う（19.2 節）。

6. 列挙型

6.1 宣言

enum Category: i8 {
    Combat,
    Item,
    Movement = 3,
    Render,          // 4
}
  • enum Name: IntType { Member [= expr], ... }。基底型 IntType は整数型でなければならず、省略できない。
  • = expr を省略したメンバの値は、直前のメンバの値 + 1（最初のメンバなら 0）。
  • 値は定数式で、基底型の範囲に収まらなければならない。
  • 同じ値のメンバが複数あってよい（別名）。同じ名前のメンバはエラー。
  • サイズとアラインメントは基底型と同じ。

6.2 使い方

  • メンバは Category::Movement のように型で修飾して書く。
  • 列挙型の値には、メンバ以外の値も入りうる（ゲームのメモリから読んだ値など）。そうした値も正当な値である。
  • 列挙型と整数型の変換は as で明示する（14.2 節）。
  • 列挙型どうしの比較は == と != だけ（大小比較は as で整数にしてから）。
  • 列挙型は名前空間の中にも、構造体の中にも書ける。

7. ジェネリクス

7.1 ジェネリック構造体

struct SharedPtr<T> {
    ptr: ?*T at 0x0;
    ctrl: ?*void at 0x4;

    #[inline]
    fn get(self) -> ?*T {
        return self->ptr;
    }
}

struct Pair<A, B> {
    first: A;
    second: B;
}
  • 型引数は 1 つ以上。型引数の名前は、構造体の関連スコープ（3.3 節）に入る。
  • ジェネリクスにできるのは構造体だけ。関数・列挙型・型別名はジェネリック引数を取れない（構造体の中の関数は、その構造体の型引数を使える）。

7.2 実体化

  • SharedPtr<Player> のように型引数を与えて使ったときに、その組み合わせの構造体が作られる（単相化）。
  • 同じ型引数の組み合わせは、コンパイル単位の中で 1 回だけ実体化される（同一性は 4.9 節）。
  • 型引数に対する制約はない。本体は、実体化した後で型検査する。エラーは、実体化した場所と本体の場所の両方を示して報告する。
  • 実体化が無限に続く場合（struct S<T> { x: ?*S<[2]T>; } を使ったときなど）は、深さの上限を超えた時点でエラーとする。上限は処理系定義（64 以上）。

7.3 式の中での型引数

型の位置（: の後、-> の後、as の後、型引数の中）では SharedPtr<Player> と書ける。

式の中では、< が比較演算子と区別できないため、型引数を ::<...> で書く。

let p = SharedPtr::<Player> { ptr: null, ctrl: null };
let n = Pair::<i32, f32>::make(1, 2.0);

7.4 Self

構造体の中では、Self はその構造体（ジェネリック構造体では、実体化した型）を表す。

struct Node<T> {
    value: T;
    next: ?*Self;       // ?*Node<T>
}

8. 関数

8.1 宣言

fn add(a: i32, b: i32) -> i32 {
    return a + b;
}

fn reset() {
    gTicks = 0;
}
  • fn name(params) [-> RetType] { body }。
  • 引数は name: Type。引数は再代入できない（let と同じ扱い）。
  • 戻り値の型を書かない関数は、値を返さない。
  • オーバーロード（同じ名前で引数の違う関数）はない。
  • デフォルト引数はない。
  • 再帰してよい（#[inline] の関数を除く）。

8.2 return と戻り値

  • 戻り値のある関数では、関数本体の末尾に到達できてはならない（17 節）。すべての経路が return expr; で終わる必要がある。
  • 戻り値のない関数では、return; だけが書ける。末尾に到達すると、そこで戻る。

8.3 引数と戻り値の型

  • 引数と戻り値には、任意のサイズ確定済みの型を書ける。構造体と配列の値渡しも可（コピーされる）。ABI は 19.2 節。ただし、ドロップされる型（8.11 節）は引数にできない。

8.4 属性

属性対象意味
#[inline]fn呼び出し箇所に本体を展開する。再帰できない。アドレスを取ると、展開しない本体が別に 1 つ作られる
#[deref]構造体のメソッドその構造体の値を、ポインタとして扱う場所で暗黙に呼ぶ（8.8 節）
#[null]構造体の関連関数その構造体として書いた null の値を返す（8.9 節）
#[iter]構造体のメソッドその構造体の値を for で回すときに暗黙に呼ぶ（8.10 節）
#[drop]構造体のメソッドその構造体の値が不要になったときに暗黙に呼ぶ（8.11 節）
#[copy]構造体のメソッドその構造体の値をコピーするときに暗黙に呼ぶ（8.11 節）
  • 属性は宣言の直前に書く。未知の属性はエラー。
  • インライン展開しても、意味は通常の呼び出しと同じ（引数はそれぞれ 1 回だけ、左から右に評価される）。

8.5 メソッド

struct Timer {
    elapsed: u32;
    interval: u32;

    fn tick(self) -> bool {
        self->elapsed += 1;
        if self->elapsed < self->interval { return false; }
        self->elapsed = 0;
        return true;
    }

    fn make(interval: u32) -> Timer {        // self なし: 関連関数
        return Timer { elapsed: 0, interval: interval };
    }
}
  • 構造体の中の関数で、最初の引数が self（型は書かない）のものをメソッドと呼ぶ。self の型は *Self（null ではない）である。
  • const self と書くと、self の型は const *Self になり、メソッドは自分の構造体に書き込めない。const self のメソッドは、const ポインタ、書き込み可能でない場所、一時的な値に対しても呼べる（8.6 節）。extern 関数にも書ける（宣言した関数が書き込まないことの約束であり、守られなければ 9.2 節と同じく未定義）。
  • self のない関数を関連関数と呼ぶ。
  • self は最初の引数にだけ書ける。

8.6 呼び出し

書き方条件意味
f(args)f が関数、または関数型の値呼び出し
T::f(args)f が構造体 T の関連関数呼び出し
T::m(p, args)m が構造体 T のメソッドp を self として渡す（p は *T に変換できる型）
p->m(args)p: *S、m が S（または祖先）のメソッド。p: const *S なら m は const selfp を self として渡す
p->m(args)p: *I、m がインターフェース I の関数。p: const *I なら m は const selfp を作ったときの構造体のメソッドを呼ぶ（5.9 節）
v.m(args)v が構造体 S の値の書き込み可能な場所（13.4 節）。m が const self なら、v は任意の値&v を self として渡す（一時的な値は一時領域に置く）
p->f(args) / v.f(args)f が関数型のフィールドそのフィールドの値を呼ぶ（self は自動では渡さない）
  • メソッドは、受け手の静的な型から、その構造体、基底、さらにその基底…の順に探す。最初に見つかったものを使う（隠蔽、5.3 節）。
  • 祖先のメソッドを呼ぶ場合、受け手は祖先の型に暗黙に変換される。
  • ?*S を受け手にしてメソッドは呼べない。取り出してから呼ぶ（15 節）。
  • const self でない m で、v が書き込み可能でない場合（let で宣言した値など）はエラー。
  • const self の m に一時的な値を渡す場合、ドロップされる型（8.11 節）の値は変数に入れてから使う。

8.7 関数の値

  • 関数の名前（f、T::f、T::m）を呼び出さずに書くと、関数型の値になる。
  • メソッド T::m の値の型は、self を *T 型の通常の引数とした関数型である。
  • extern fn の値も取れる。hook 宣言と original は値として取れない。
  • const self のメソッド T::m の値の型では、self は const *T 型の引数になる。

8.8 参照外し関数 #[deref]

struct shared_ptr<T> {
    ptr: ?*T at 0x0;
    count: ?*void at 0x4;

    #[inline]
    #[deref]
    fn get(const self) -> ?*T { return self->ptr; }
}

let player = minecraft->mThePlayer orelse return;   // minecraft->mThePlayer.get() orelse return
if let target = minecraft->mTargetEntity { ... }     // if let target = minecraft->mTargetEntity.get()
  • #[deref] を付けたメソッドを参照外し関数と呼ぶ。形は fn name(self) -> ?*T または fn name(self) -> *T（T は構造体）でなければならない。
  • 構造体 S（または祖先）が参照外し関数を持つとき、S の値 x を次の位置に書くと、x.name() と書いたものとして扱う。
    • x->f（13.5 節）
    • x orelse ... の左辺（13.14 節）
    • if let / while let の expr（12.6 節、12.7 節）
  • それ以外の位置（代入、引数、return、比較など）では変換しない。必要なら明示的に呼ぶ。
  • 8.6 節の v.m() と違い、x は書き込み可能な場所でなくてよい。let 変数や関数の戻り値にも使える。場所でない値は一時領域に置いてから、そのアドレスを渡す。書き込み可能でない場所（let 変数、引数、const ポインタを通った場所、それらのフィールド）は、参照外し関数が const self ならそのまま const *S として、そうでなければ一時領域にコピーしてから渡す。そのため、x 自身が書き換えられることはない。
  • 参照外し関数が ?*T を返す場合、x->f はエラーになる（null かもしれないため、15 節）。orelse か if let で取り出してから使う。
  • 1 つの構造体（祖先を含む）に参照外し関数が複数ある場合は、8.6 節のメソッド探索と同じく最初に見つかったものを使う。
  • 参照外し関数を持つ構造体の値 x と null を == / != で比べると、x.name() == null として扱う。

8.9 null 値関数 #[null]

struct shared_ptr<T> {
    ...
    #[inline]
    #[null]
    fn empty() -> Self { return Self { ptr: null, count: null }; }
}

fn GetPlayer() -> shared_ptr<Player> {
    let minecraft = Minecraft::GetInstance() orelse return null;   // shared_ptr::empty()
    return minecraft->mThePlayer;
}
var gTarget: shared_ptr<Entity> = null;
  • #[null] を付けた関連関数をnull 値関数と呼ぶ。形は fn name() -> Self でなければならない。
  • 構造体 S が null 値関数を持つとき、null は S に暗黙に変換でき、その関数の戻り値になる。祖先の null 値関数は使わない。
  • 本体が定数式を 1 つ return するだけなら、その定数を直接使う（関数は呼ばれない）。グローバル変数の初期化式にも書ける。そうでなければ、変換のたびに関数を呼ぶ。
  • null 値関数の戻り値は、参照外し関数（8.8 節）が null を返す値にするべきである。コンパイラはこれを検査しない。

8.10 反復関数 #[iter]

struct vector<T> {
    start: ?*T at 0x4;
    finish: ?*T at 0x8;

    #[inline]
    #[iter]
    fn slice(const self) -> []T {
        let first = self->start orelse return null;
        let last = self->finish orelse return null;
        return first[0..(last - first) as u32];
    }
}

for it in level->mEntities { ... }   // it: *shared_ptr<Entity>
  • #[iter] を付けたメソッドを反復関数と呼ぶ。形は fn name(self) -> []T でなければならない（const self と const []T でもよい）。
  • for name in x（12.9 節）の x が、反復関数を持つ構造体の値、またはその構造体への *S / const *S なら、反復関数を 1 回呼び、返ったスライスを回す。
  • 反復関数は、構造体自身と、その基底、さらにその基底…の順に探し、最初に見つかったものを使う。
  • 参照外し関数（8.8 節）と同じく、x は書き込み可能な場所でなくてよく、同じ規則で self が渡される（const *S の x は、書き込み可能でない場所 x.* として扱う）。

8.11 ドロップ関数 #[drop] とコピー関数 #[copy]

struct shared_ptr<T> {
    ptr: ?*T at 0x0;
    count: ?*void at 0x4;

    #[drop]
    fn release(self) {
        ReleaseSharedCount(&self->count, false);
        self->ptr = null;
        self->count = null;
    }
}

fn Send(listener: *ClientPacketListener) {
    var packet: shared_ptr<Packet> = null;
    Packet::create(&packet);
    listener->send(&packet);
}   // ここで packet.release() が呼ばれる
  • #[drop] を付けたメソッドをドロップ関数と呼ぶ。形は fn name(self) でなければならない（const self は不可）。1 つの構造体に 1 つまで。
  • 次の型をドロップされる型と呼ぶ。
    • ドロップ関数を持つ構造体
    • ドロップされる型のフィールドを持つ構造体、ドロップされる型を基底に持つ構造体
    • ドロップされる型の配列
  • 値をドロップするとは、次の順に行うことである。
    • 構造体: 自身のドロップ関数（あれば）、自身のフィールドを宣言の逆順にドロップ、基底をドロップ
    • 配列: 要素を先頭から順にドロップ
  • ドロップは次のときに行われる。
    • ドロップされる型のローカル変数（let / var）が、そのブロックを抜けるとき。ブロックの終わり、return、break、continue（orelse return/break/continue を含む）のどれで抜けても行い、後に宣言したものから順に行う（defer とも合わせて逆順。12.14 節）。return の値は、ドロップの前に計算される。
    • ドロップされる型の場所に代入するとき。右辺を計算した後、古い値をドロップしてから書き込む。ローカル変数、グローバル変数、ポインタの先のどれでも同じ。
    • 式文で、呼び出しが返したドロップされる型の値を捨てるとき。その場でドロップする。
  • グローバル変数はドロップされない（代入で古い値がドロップされるだけ）。
  • 既存の場所（変数、フィールド、.* など）を、初期化・代入・return・構造体リテラル・配列リテラル・new の値に使うことをコピーと呼ぶ。ドロップされる型の値のコピーは、次のとおり。
    • その構造体自身がコピー関数（#[copy] を付けたメソッド）を持つなら、x.name() と書いたものとして扱い、その戻り値を使う。x は参照外し関数（8.8 節）と同じく、書き込み可能な場所でなくてよく、同じ規則で self が渡される。
    • 持たないなら、エラーになる。基底やフィールドのコピー関数は使わない（配列も同じ）。
    • ローカル変数をそのまま return するのは、コピーではなく移動になり、コピー関数は呼ばれず、その変数はドロップされない。
  • ドロップされる型は、値渡しの引数にできない。関数の引数の型にも書けない。*S を使う。
  • コピー関数の形は fn name(self) -> Self でなければならない（const self でもよい）。1 つの構造体に 1 つまで。ドロップされる型にしか付けられない（ほかの構造体はバイト単位でコピーされる）。返す値は新しい値として扱われ、後でドロップされる。コピー関数の中でその構造体自身をコピーすることはできない（自分を呼び続けるため）。直接呼んでもよい。
struct shared_ptr<T> {
    ...
    #[copy]
    fn retain(const self) -> Self {
        var out = Self { ptr: self->ptr, count: null };
        AcquireSharedCount(&out.count, &self->count);   // 参照を 1 つ増やす
        return out;
    }
}

for it in level->mEntities {
    let entity = it.*;                     // entity = it.*.retain()
    let e = entity orelse continue;
    ...
}                                          // entity がドロップされ、参照が 1 つ減る
  • 呼び出しが返した値などの一時的な値は、そのまま ->、.、添字、?、orelse、if let、for に使えない。変数に入れてから使う（使っている間にドロップされないようにするため）。
  • 構造体リテラル・配列リテラルが、ドロップされる型のフィールドや要素の値を含むとき、その中では orelse return/break/continue（ブロックの形を含む）を使えない。途中で抜けると、作りかけの値がドロップされずに残るため。先に let で計算しておく。
  • ドロップ関数は直接呼べない。値を早く手放すには、null など別の値を代入する。
  • ドロップされる型のフィールドは、他のフィールドとメモリを共有できない。
  • ドロップされる型の値を、&x を渡した関数が上書きした場合、古い値はドロップされない。そのような関数には、空の値（null など）を渡す。

8.12 コンストラクタとデストラクタ

struct Note {
    count: i32;

    fn make(count: i32) -> Self { return Self { count: count }; }
}

let a = Note::make(1);                        // スタックに作る
let p = new Note::make(2) orelse return;      // ヒープに作る（13.17 節）
defer delete p;

struct Zombie : Monster {
    extern fn __ct(ptr: ?*Self, level: ?*Level) -> ?*Self at 0x02003000;
    extern fn __dt(self, disposing: bool) at 0x02003010;
}

let z = Zombie::__ct(null, level) orelse return;   // ゲームのコンストラクタ
defer z->__dt(true);                                // ゲームのデストラクタ
  • 言語にコンストラクタとデストラクタの仕組みはない。Self を値で返す関連関数を、慣習としてコンストラクタと呼ぶ。名前は自由。
  • 処理系は、コンストラクタもデストラクタも（基底のものも含めて）暗黙に呼ばない。基底部分を作るのも、破棄するのも、その型を書く人の責任である。ドロップ関数とコピー関数（8.11 節）だけは暗黙に呼ばれる。
  • ゲーム（GHS）のコンストラクタは普通の extern 関数として宣言する。ptr が null なら自分の型のサイズをゲームの operator new で確保し（できなければ null を返す）、null でなければ ptr の指すメモリを使う。そのうえで、基底のコンストラクタを自分で呼んでから、自分の部分を作る。作り済みのオブジェクトに対して呼ぶと二重に初期化されるため、空きメモリに対してだけ呼ぶ。
  • ゲームのデストラクタ（__dt など）も普通の extern 関数で、手動で呼ぶ。delete もスコープの終わりも、これを呼ばない。GHS のデストラクタは、disposing が真ならメモリの解放まで行う。

9. extern 宣言

9.1 構文

// 固定アドレスの関数
extern fn GetInstance() -> ?*Minecraft at 0x02001000;

// ホストが名前で提供する関数
extern fn Notify(module: cstr, message: cstr) -> u32 from "host";

// 構造体の中: メソッド（self あり）と関連関数（self なし）
struct Vec3 {
    extern fn length(self) -> f64 at 0x02005000;
    extern fn newTemp(x: f64, y: f64, z: f64) -> *Vec3 at 0x02006000;
}
  • extern fn name(params) [-> RetType] LOCATION;
  • LOCATION は次のどちらか。
    • at ADDR: ADDR は型なし整数定数か u32 の定数式。固定アドレスを表す。
    • from "PROVIDER": ロード時にホストが、提供元 PROVIDER と関数名 name の組で解決する。提供元 "cafe" は処理系の実行時ヘルパー用に予約されており、書くとエラー。
  • extern 宣言は本体を持たない。

9.2 意味

  • extern 関数は、通常の関数と同じ書き方で呼べる（8.6 節）。
  • 呼び出しは、19 節の呼び出し規約に従う。
  • from の関数をホストが解決できなかった場合、ロードは失敗する（ホストはエラーを報告する）。
  • extern 宣言のアドレスとシグネチャが実体と一致することは、コンパイラには検査できない。一致しない場合の動作は未定義である（18 節）。

9.3 引数名

extern 宣言では引数名を省略できる。

extern fn set(self, f64, f64, f64) at 0x02006010;

9.4 可変長引数

extern fn OSReport(fmt: cstr, ...) at 0x0123_4567;
  • 引数の並びの最後に ... を書ける。... の部分に渡した実引数は、次の規則で渡す。
    • 型なし整数定数は i32、型なし浮動小数点定数は f64 として扱う。
    • f32 は f64 に昇格する。
    • bool, i8, i16, u8, u16 は i32 / u32 に拡張する。
    • 構造体と配列の値は渡せない。
  • 可変長引数を持つ extern 関数は、値として取れない（4.4 節）。

9.5 const の引数

struct MultiPlayerGameMode {
    extern fn attack(self, player: const *shared_ptr<Player>, entity: const *shared_ptr<Entity>) at 0x02002000;
}
struct Mob {
    extern fn getTarget(self, result: *shared_ptr<LivingEntity>) at 0x02004000;   // 書き込む引数
}

gameMode->attack(&minecraft->mThePlayer, it);   // *shared_ptr<MultiplayerLocalPlayer> を渡せる
mob->getTarget(&zombie);                        // エラー: shared_ptr<Zombie> に LivingEntity が書かれうる
  • C++ の値渡しと const& の引数は、const ポインタ（4.2 節）の引数として宣言する。extern 関数の本体は検査できないため、const は宣言した関数が書き込まないことの約束である。const の引数に書き込む関数を const 付きで宣言した場合、動作は未定義（9.2 節と同じく、宣言と実体の不一致）。
  • const ポインタへは、メモリを別の型として読む変換もできる（14.1 節の 6）。shared_ptr<MultiplayerLocalPlayer> を const *shared_ptr<Player> に渡せるのはこのためである。const でない引数にこの変換はできない。関数が別の型の値を書き込みうるため（C++ で、変換した一時オブジェクトを非 const の参照に渡せないのと同じ）。

10. hook 宣言

10.1 構文

hook mc::Entity::tick(self) {
    original(self);
    self->mMotion.y += 0.01;
}

hook mc::Gui::render(self, partialTicks: f32) {
    original(self, partialTicks);
    drawOverlay();
}
  • hook PATH(params) [-> RetType] { body }
  • PATH は、at で宣言された extern 関数を指さなければならない（from の関数はフックできない）。
  • 引数の型の並びと戻り値の型は、extern 宣言と完全に一致しなければならない（const を含む）。引数名は自由（self はメソッドの場合に必須で、extern 宣言が const self なら const self と書く）。
  • hook 宣言は、エントリファイルのトップレベル（名前空間の外）にだけ書ける。
  • コンパイル単位の中で、同じ extern 関数に hook を 2 つ書くとエラー。

10.2 original

  • hook の本体の中では、original は、フック対象の元の処理（ホストのフックチェーンで次に呼ばれるもの）を表す。
  • original(args) の引数と戻り値は、extern 宣言と同じ。
  • original は 0 回呼んでも、複数回呼んでもよい。
  • original は hook の本体の外では使えない。値として取ることもできない。

10.3 意味

  • hook はホストに登録され、ホストがフック対象のアドレスにパッチを当てる。パッチの方式と、同じアドレスへの複数のフックをチェーンする方法は、ホストの責任である。
  • フックされた関数がどのスレッドから呼ばれるかは、ゲーム側によって決まる。スクリプトの他の関数と同時に実行される可能性がある（18 節）。

11.4 グローバル変数

var gTicks: u32 = 0;
let gConfig = Config { speed: 2.0 };
  • トップレベル（名前空間の中も可）で宣言する。
  • 初期化式は定数式でなければならない（16 節）。
  • 実体は、コンパイル結果のデータ領域に置かれる。モジュールが読み込まれている間は保持され、再読み込みすると初期値に戻る。
  • トップレベルの let は、読み取り専用データ領域に置いてよい。

11.5 const

  • const は名前の付いた値であり、場所を持たない。& で取れない。
  • 型注釈を省略した const に型なし定数を書いた場合、その const も型なし定数になる（使う場所の文脈で型が決まる）。
  • 構造体の中、名前空間の中、トップレベル、関数本体の中に書ける。

12.3 代入

place = expr;
place += expr;     // -= *= /= %= &= |= ^= <<= >>= も同様
  • 左辺は書き込み可能な場所（13.4 節）でなければならない。
  • 代入は文であり、式ではない（値を持たない）。
  • 評価順序: 左辺の場所を決める部分式を左から右に評価し、次に右辺を評価し、最後に格納する。
  • place op= expr は place = place op expr と同じ意味だが、place を決める部分式は 1 回だけ評価する。

  • 式を文として書けるのは、関数呼び出しだけ。戻り値は捨ててよい。
  • 呼び出し以外の式（x + 1;、null; など）を文として書くとエラー。

12.5 if

if a > b {
    ...
} else if a == b {
    ...
} else {
    ...
}
  • 条件は bool 型でなければならない。条件を括弧で囲む必要はない。
  • 本体は必ずブロック。

12.6 if let

if let p = gTarget {
    p->mGlowing = true;       // p: *Entity
} else {
    ...
}
  • if let name = expr { } [else ...]
  • expr は ?*T 型（または ?fn(...) 型）でなければならない。参照外し関数を持つ構造体の値なら、それを呼んだ結果を使う（8.8 節）。
  • expr が null でなければ、name を *T（または fn(...)）型の let 変数として束縛し、最初のブロックを実行する。null なら else を実行する。
  • name が有効なのは最初のブロックの中だけ。
  • else if let ... も書ける。

12.7 while と while let

    i += 1;
}

while let n = node {
    total += n->value;
    node = n->next;
}
  • while cond { }: cond は bool。
  • while let name = expr { }: 毎回 expr を評価し、null でなければ束縛して本体を実行する。null なら終了する。

12.8 loop

loop {
    if done() { break; }
}
  • 無限ループ。break で抜ける。

12.9 for

for i in 0..10 { ... }                       // i: i32, 0〜9
for i in 0..buf.len { buf[i] = 0; }
for it in v->begin..v->end { ... }           // it: *T, 要素サイズ単位で進む
for it in slice { ... }                      // it: *T, スライスの各要素
for it in gArray { it.* = 0; }               // it: *T, 配列の各要素
for it in level->mEntities { ... }           // 反復関数（8.10 節）が返すスライスの各要素

範囲の for

  • for name in a..b { }
  • a と b は、同じ整数型、または同じポインタ型 *T でなければならない（片方が型なし定数なら、もう片方の型に合わせる。両方とも型なし定数なら i32。片方が暗黙にもう片方の型に変換できるなら、その型に合わせる）。
  • a と b は、ループの開始前に 1 回ずつ、左から右に評価する。
  • name は各回で let として束縛される。値は a, a+1, …, b-1（ポインタなら 1 要素ずつ進む）。a >= b なら 1 回も実行しない。
  • 整数の範囲で、b が型の最小値のときなど、b-1 を計算しても溢れない。ループは「現在値 < b」の間続く。

要素の for

  • for name in x { }（.. がない形）。x は次のいずれかでなければならない。
    • スライス []T / const []T
    • 配列 [N]T。一時的な配列はスタックに置かれる。
    • 反復関数を持つ構造体 S の値、または *S / const *S（8.10 節）
  • x はループの開始前に 1 回だけ評価する（反復関数も 1 回だけ呼ぶ）。
  • name は *T 型の let として束縛され、各要素を指す。要素を書き換えるには name.* や name->f に書き込む。const []T と書き込み可能でない配列（let で宣言した配列など）では、name は const *T 型になる。
  • 空のスライス（len が 0）なら 1 回も実行しない。ループ中に元のコンテナの要素数が変わった場合の動作は未規定である（開始時の範囲を回る）。

12.10 match

match lang {
    Language::Japanese => { ... }
    Language::English, Language::French => { ... }
    _ => { }
}

match gTicks {
    180 => { ... }
    360 => { ... }
    _ => { }
}
  • 対象の式は、整数型・列挙型・bool のいずれか。
  • 各アームは パターン [, パターン ...] => { ブロック }。アームの本体は必ずブロックで、アームの後に , は書かない。
  • パターンは、対象の型の定数式（列挙型ならメンバも可）か、_（ワイルドカード）。
  • 同じ値が 2 つのパターンに現れるとエラー。_ は最後のアームにだけ、単独で書ける。
  • 対象の式は 1 回だけ評価する。上から順に照合し、最初に一致したアームを実行する。フォールスルーはない。
  • 網羅性:
    • bool: true と false の両方を書くか、_ が必要。
    • 整数型: _ が必要。
    • 列挙型: _ を省略できるのは、すべてのメンバを書いた場合だけ。その場合でも、メンバ以外の値（6.2 節）にはどのアームも一致せず、何も実行しない。

12.11 break / continue

  • break; は、最も内側の while / while let / loop / for を抜ける。
  • continue; は、最も内側のループの次の回に進む（for なら次の値へ）。
  • ラベル付きの break / continue はない。
  • ループの外で使うとエラー。

12.12 return

  • return expr;（戻り値のある関数）、return;（戻り値のない関数）。

12.13 delete

let note = new Note { count: 1 } orelse return;
note->count += 1;
delete note;
  • delete expr;。expr は *T か ?*T（T はサイズの決まった型。*void は不可）、または *I か ?*I（5.9 節）。const ポインタ（4.2 節）は不可。
  • *I の場合は、それを作ったときの構造体の型 T について同じことをする（関数表の削除関数を呼ぶ）。
  • expr を 1 回だけ計算する。null なら何もしない。null でなければ、指す先の値を expr の静的な型 T としてドロップし（8.11 節）、メモリを new の確保元に返す。
  • new で値から作ったメモリ（13.17 節）にだけ使える。それ以外のポインタや、delete 済みのポインタに使った場合の動作は未定義（18.1 節）。
  • T は new で作った値の型と同じでなければならない。派生型の値を基底のポインタで delete した場合の動作は未定義（派生側のフィールドがドロップされない。仮想デストラクタはない）。
  • ゲームのデストラクタ（8.12 節）は呼ばない。ゲームのオブジェクトは、そのデストラクタを手動で呼んで破棄する。
  • delete しても、ポインタの値は変わらない。

12.14 defer

fn Spawn(level: *Level) {
    let z = Zombie::__ct(null, level) orelse return;
    defer z->__dt(true);           // どの経路で抜けても最後に実行される

    let note = new Note::make(1) orelse return;   // ここで return しても z は破棄される
    defer delete note;

    if !setup(z) { return; }       // note → z の順に後始末される
    defer {
        log("done");
        gCount += 1;
    }
}
  • defer 文。書ける文は、呼び出し、代入、delete、ブロック { ... } のいずれか。
  • defer 文に到達した時点で登録され、それを含むブロックを抜けるときに実行される。抜け方は問わない（ブロックの終わり、return、break、continue、orelse return/break/continue を含む）。到達しなかった defer は実行されない。
  • 実行の順序は登録の逆順で、ローカル変数のドロップ（8.11 節）とも合わせて逆順になる。そのため、defer より前に宣言した変数は、その defer が実行された後にドロップされ、defer の中で安全に使える。
  • 名前は defer 文の位置で解決する。
  • return expr; の expr は、defer を実行する前に計算される。
  • defer の中から外へ抜けることはできない。return、defer の外のループへの break / continue、orelse return/break/continue はエラー。defer の中のループの break / continue は書ける。
  • defer の中の defer は、defer の中のブロックを抜けるときに実行される（普通のブロックと同じ）。

13.2 型なし定数

  • 整数リテラル、文字リテラル、浮動小数点リテラル、型注釈のない const、およびそれらだけからなる定数式は、型なし定数である。
  • 型なし定数は、使われた文脈の型（代入先・引数・演算の相手の型など）に変換される。

  • 型なし定数どうしの演算は、精度を落とさずにコンパイル時に計算する（整数は少なくとも 128 ビット精度、浮動小数点数は f64 精度）。

13.4 場所と書き込み可能性

場所（place）とは、メモリ上の位置を表す式である。次のものが場所になる。

  • 変数（let、var、引数、self は除く。self は値）
  • p->f（p が *T 型の式）
  • x.f（x が構造体の値の場所）
  • p.*（p が *T 型の式）
  • a[i]（a が配列の場所、または *T 型の式）
  • s[i]（s がスライス）

場所が書き込み可能かどうかは、次のように決まる。

  • var で宣言した変数は書き込み可能。let で宣言した変数と引数は書き込み可能でない。
  • p->f, p.*, p[i]（p がポインタ）, s[i]（s がスライス）は、p / s が const でなければ書き込み可能（参照外しを通った場所）。const なら書き込み可能でない。
  • x.f と x[i]（x が値）は、x が書き込み可能なときだけ書き込み可能。

書き込み先の規則: 書き込み可能な場所が参照外し（->, .*, ポインタの添字）を通っていれば、その書き込みはポインタの指す先のメモリに対するものである。通っていなければ、スクリプト自身の変数（ローカル変数かグローバル変数）に対するものである。

  • ポインタに . を使う、または値に -> を使うとエラー（暗黙の参照外しはしない）。ただし参照外し関数を持つ構造体の値には -> を使える（8.8 節）。
  • ?*S には -> も .* も使えない。
  • 基底のフィールドは、派生型から直接アクセスできる。
  • priv のフィールドは、宣言したファイルの中からだけアクセスできる。
  • a.len は配列の要素数（4.3 節）。スライスの s.len と s.ptr は 4.3 節を参照。

13.7 算術演算

+ - * / % は、両辺が同じ数値型でなければならない（型なし定数は相手の型に合わせる）。暗黙の拡張はしない（i32 + i64、f32 + f64 はエラー）。

整数

  • 結果はその型で 2 の補数のラップアラウンドをする（オーバーフローはエラーではない）。
  • / は 0 方向に切り捨てる。% の結果の符号は左辺と同じ（a == (a / b) * b + a % b）。
  • 0 で割った場合、および符号付きの最小値を -1 で割った場合の結果は未規定（トラップはしない。18 節）。

浮動小数点数

  • IEEE 754 に従う。f32 の演算は単精度で、f64 の演算は倍精度で行う。
  • % は浮動小数点数には使えない。

単項 -

  • 数値型に使える。符号なし整数では 2 の補数（0 - x）。

13.9 比較演算

  • == と !=: 両辺が同じ型（暗黙の変換の後）の、数値・bool・列挙型・ポインタ・関数型のいずれか。?*T と null も比較できる。*T と null は比較できない（*T は null にならない型のため。15.3 節）。
  • < > <= >=: 両辺が同じ数値型、または同じポインタ型 *T（アドレスを符号なしで比較）。
  • 結果は bool。
  • 浮動小数点数の比較は IEEE 754 に従う（NaN は != 以外すべて false）。
  • 構造体と配列は比較できない。
  • インターフェースへのポインタ ?*I は、null とだけ比較できる（5.9 節）。

13.10 論理演算

  • !x, x && y, x || y のオペランドは bool。結果は bool。
  • && と || は短絡評価する（左辺で結果が決まれば右辺を評価しない）。

13.11 ビット演算とシフト

  • & | ^: 両辺が同じ整数型。~x: 整数型。
  • << と >>: 左辺は整数型。右辺は任意の整数型（左辺と同じ型である必要はない）。結果は左辺の型。
    • >> は、符号付き整数では算術シフト、符号なし整数では論理シフト。
    • シフト量が負、または左辺の型のビット幅以上のときの結果は未規定（18 節）。
  • bool にビット演算は使えない。

13.13 アドレス演算子 &

  • &place は、場所 place（13.4 節）のアドレスを返す。型は、place が書き込み可能なら *T、書き込み可能でない（let の変数、引数、const ポインタを通った場所など）なら const *T。
  • const と一時値（関数の戻り値など）のアドレスは取れない。
  • 関数のアドレスは & を付けずに関数名で取る（8.7 節）。

  • x が null なら、その場でトラップする（tweqi 命令）。処理は先に進まず、例外ハンドラの SRR0 がその ? の位置を指す。
  • null になりうる値（タイトル画面での mThePlayer など）には使わず、orelse か if let を使う。
  • 後置演算子なので、a?->b?->c のように続けて書ける。as の結果に付けるには括弧が要る（(x as ?*T)?）。

13.16 評価順序

  • 二項演算のオペランド、関数呼び出しの実引数（受け手を含む）、構造体リテラル・配列リテラルの要素は、書かれた順に左から右へ評価する。
  • 呼び出す関数を表す式（関数ポインタの式など）は、実引数より先に評価する。
  • &&, ||, orelse は 13.10 節と 13.14 節に従う。
  • new expr の expr は、メモリを確保した後に評価する（13.17 節）。

13.17 new

let note = new Note { count: 1, pos: v } orelse return;   // ?*Note
let other = new Note::make(2) orelse return;              // コンストラクタ（8.12 節）の結果を直接書き込む
  • new expr。@sizeof(T) バイト（0 なら 1）を確保し、確保できたときだけ expr を評価して、そのメモリに直接書き込む。結果は ?*T で、確保できなければ null になる。T は expr の型（型なし定数は 13.2 節の既定の型）。
  • expr が値を返す呼び出しなら、確保したメモリが戻り値の領域として渡され、そこに直接書かれる（コピーされない）。構造体リテラルで省略したフィールドは、ゼロ値になる。ほかに呼ばれるものはない（8.12 節）。
  • T がポインタ型・関数型ならエラー。ポインタを返す関数（ゲームのコンストラクタなど）は、自分で確保するので new を付けずに呼ぶ。
  • 既存の場所（変数など）のドロップされる型（8.11 節）の値を書くと、コピーになる（コピー関数がなければエラー）。
  • expr の中では orelse return/break/continue（ブロックの形を含む）を使えない。途中で抜けると、確保したメモリが残るため。
  • new の結果を捨てるとエラー（式文にはできない）。
  • 確保したメモリは自動では解放されず、中の値もドロップされない。delete（12.13 節）で解放する。
  • new x? の ? は、new の結果に掛かる（(new x)? と同じ）。
  • メモリは、提供元 "cafe" の実行時ヘルパー __cs_alloc / __cs_free で確保・解放する。__cs_alloc(size: u32) -> ?*void は 8 バイト境界で確保し、確保できなければ null を返す。

14.1 暗黙の変換

暗黙の変換は、次の 6 種類だけである。

3null任意の ?*T / ?fn(...)、スライス []T（空のスライス）、null 値関数を持つ構造体（8.9 節）
4*Derived / ?*Derived*Base / ?*Base（Base が Derived の祖先）、*I / ?*I（I は Derived が実装するインターフェース。5.9 節）

  • 4 は、1 段のポインタにだけ適用する。*?*Derived → *?*Base のように、ポインタの指す先の型を変える変換はしない（?*Base を書き込めてしまうため）。指す先に書き込めない 6 では、次の条件で指す先の型を変えられる。
  • 6 で「A のメモリを B として読める」とは、次のいずれかである。スライスでは、さらに A と B のサイズが同じでなければならない。
    • A が B と同じか、B を祖先に持つ構造体。
    • A と B がポインタで、この節の変換で A から B へ変換できる（?*Derived を ?*Base として読むなど）。
    • A と B が同じジェネリック構造体の実体で、参照外し関数（8.8 節）を持ち、サイズ、基底、全フィールドのオフセットが同じで、各フィールドの型がこの条件を満たす（shared_ptr<MultiplayerLocalPlayer> を shared_ptr<Player> として読むなど）。参照外し関数を持つ構造体は 1 つのオブジェクトを指すものとして扱い、配列を指しうる構造体（vector<T> など）は対象にしない。
  • 格納されたポインタは 1 段だけ変換する（*?*?*Derived は const *?*?*Base に変換できない）。指す先のメモリには書き込めなくても、そこに入っているポインタの指す先には書き込めるため。
  • 暗黙の変換が行われるのは、代入・初期化・引数渡し・戻り値・二項演算の相手の型に合わせる場合・orelse の右辺である。

15. null 安全性

15.1 原則

  • null かもしれない値は ?*T（?fn(...)）型で表す。
  • ?*T の値は、代入・比較・引数渡し・返却・フィールドへの格納を自由に行える。
  • ?*T の値を参照外し（->, .*, 添字、メソッド呼び出し、関数呼び出し）するには、先に *T に取り出す必要がある。取り出す方法は次の 4 つだけ。
    • orelse（13.14 節）
    • if let（12.6 節）
    • while let（12.7 節）
    • 後置 ?（13.14 節。null ならトラップする）

15.2 型の絞り込みはしない

if p != null { ... } の中でも、p の型は ?*T のままである。比較の結果を使って型を変えることはしない。

15.3 最適化の前提にしない

コンパイラは、*T 型の値が null でないことを、最適化の前提に使ってはならない。 *T は型検査のためだけの区別であり、生成コードには影響しない。

そのため、外部の宣言が誤っていて *T に 0 が入った場合でも、(p as ?*T) == null のような比較は省略されずに実行される（*T は null と直接比べられない。13.9 節）。

15.4 *T に null が入りうる経路

次の経路では、*T に 0 が入る可能性がある。これらは型システムの外側であり、プログラマ（またはバインディング生成器）の責任である。

  • extern 宣言の戻り値・引数の型が、実体と食い違っている（9.2 節）
  • ゲームのメモリを表す構造体で、ポインタフィールドを *T と宣言したが、実際には null が書き込まれる
  • ポインタ間の as で、指す先のメモリの内容を誤って解釈した
  • ポインタ演算の結果が 0 になった

バインディング生成の規則（推奨）: 外部のメモリや関数に由来するポインタは、既定で ?*T とする。*T にするのは、null にならないことを確認したもの（this を返す関数など）だけとする。

16. 定数式

定数式は、コンパイル時またはロード時の再配置だけで値が決まる式である。次の場所では定数式が必要になる。

  • const の初期化式
  • グローバル変数の初期化式
  • at のオフセット・アドレス、#[size(N)]、配列の要素数、列挙型のメンバの値
  • match のパターン

定数式に書けるのは、次のものだけである。

  • リテラル、true, false, null
  • const、列挙型のメンバ
  • 単項演算子と二項演算子（&& と || を含む）、as（数値型どうし、列挙型、整数からポインタへの変換）
  • @sizeof, @alignof, @offsetof, @bitcast
  • 構造体リテラル、配列リテラル（要素がすべて定数式）
  • 再配置で決まる値（グローバル変数の初期化式と const の初期化式でのみ可）
    • 文字列リテラル
    • 関数名（関数の値）
    • &g、&g.f、&g[i]（g は var のグローバル変数、i は定数式）
    • これらを暗黙の変換（14.1 節）で *I / ?*I にした値

再配置で決まる値は、演算のオペランドにはできない（そのまま格納するだけ）。ただし p + n（n は定数式）は可とする。

at, #[size], 配列の要素数、列挙型の値、match のパターンでは、再配置で決まる値は使えない（コンパイル時に値が決まる必要がある）。

17. 到達可能性

関数の末尾（8.2 節）と orelse のブロックの末尾（13.14 節）に到達できるかどうかは、次の規則だけで判定する。値の解析はしない（if true { return; } の後ろも到達できるものとみなす）。

文 S が末尾に到達しないのは、次の場合である（defer 文は、その位置では何もしないので常に末尾に到達する）。

  • return、break、continue
  • 最後の文が末尾に到達しないブロック
  • else があり、すべての分岐が末尾に到達しない if（if let も同様）
  • 本体に（その loop を対象とする）break を含まない loop
  • _ のアーム（または網羅的なアーム群）を持ち、すべてのアームが末尾に到達しない match

ブロックの中で、末尾に到達しない文の後ろに文があると、警告を出す（到達できないコード）。

18. 未定義動作と未規定動作

18.1 未定義動作

次の場合、プログラムの動作は未定義である（クラッシュする、ゲームのメモリが壊れる、など）。

  • 不正なアドレスへの参照外し（0 を含む。*T に 0 が入った場合を含む）
  • 配列やポインタの範囲外へのアクセス
  • 型が実体と一致しないメモリの読み書き（as で誤った型にした場合など）
  • extern 宣言のアドレスやシグネチャが実体と一致しない
  • 複数のスレッドから同じメモリに、同期なしで同時に書き込む（または読み書きする）
  • #[inline] でない関数で、スタックが溢れるほど深く再帰する
  • new で値から作ったのでないポインタや、delete 済みのポインタを delete する。delete 済みのメモリにアクセスする
  • as で const を外したポインタ（4.2 節）を通して、書き込み可能でない場所（let の変数、引数、文字列リテラル）に書き込む。const ポインタへの 14.1 節の 6 の変換で別の型として見ているメモリに、as で const を外して書き込む
  • const の引数（9.5 節）や const self の extern 関数が、実際にはそれを通して書き込む

18.2 未規定動作

次の場合、結果の値は未規定だが、トラップせず、プログラムの他の部分には影響しない。

  • 整数の 0 除算、符号付き最小値 ÷ -1（/ と %）
  • シフト量が負、または左辺のビット幅以上
  • 浮動小数点数から整数への変換で、範囲外または NaN
  • p - q で、差が要素サイズで割り切れない

19.1 対象

  • PowerPC 32 ビット、ビッグエンディアン（Wii U Espresso）
  • 呼び出し規約は PowerPC EABI（SVR4 ABI）に従い、ゲーム（GHS コンパイラ）の関数と相互に呼び出せる。

19.3 呼び出しの生成

  • at の extern 関数、from の extern 関数、関数ポインタの呼び出し、インターフェースの関数の呼び出し（関数表から読んだアドレス）は、アドレスを ctr に読み込んで bctrl する。
  • スクリプト内の関数どうしの呼び出しは、相対分岐（bl）でよい。

19.4 出力

コンパイル結果は、少なくとも次のものを含む。

  • コード領域（.text）
  • 読み取り専用データ領域（文字列リテラル、トップレベルの let）
  • 読み書き可能なデータ領域（グローバル変数、export const のデータ記号）
  • 再配置情報（データ領域内のアドレス、関数のアドレス、from の extern の解決先）
  • export された記号の一覧（名前、種類、オフセット）
  • hook の一覧（フック対象のアドレス、hook 本体のオフセット、original の値を格納する場所のオフセット）

ホストは、original を格納する場所に、hook を有効にする前にフックチェーンの次の関数のアドレスを書き込む。

19.5 内部記号

export されていない宣言の記号名は、正式名と定義したファイルから処理系が決める。異なるファイル・名前空間の同じ名前が、出力で衝突することはない。

20. 診断

20.1 エラー

この仕様で「エラー」と書いたものはすべてコンパイルエラーであり、コンパイル結果を出力しない。

エラーメッセージには、ファイル、行、桁を含める。ジェネリクスの実体化に由来するエラーでは、実体化した場所も示す。

20.2 必須の警告

  • orelse null（13.14 節）
  • 到達できないコード（17 節）
  • コピーへの書き込みが失われる: 参照外しを通らない場所（スクリプト自身の変数）に、構造体・配列の値を let / var でコピーし、そのフィールドや要素に書き込んだ後、その変数を一度も読まないままスコープを抜ける場合。ゲームのメモリを書き換えたつもりでコピーを書き換えている可能性を知らせる。
var abilities = player->mAbilities;   // コピー
abilities.mFlying = true;             // 警告: abilities は以後読まれない
  • 使われていないローカル変数（_ で始まる名前は除く）

21. 文法（EBNF）

表記: { X } は 0 回以上の繰り返し、[ X ] は省略可能、| は選択、"..." は字句。

File            = { TopItem } ;

TopItem         = Import | Use | Namespace | Hook
                | [ "export" ] Decl
                | [ "priv" ] Decl ;

Import          = "import" StringLit ";" ;
Use             = "use" Path [ "as" Ident ] ";" ;
Namespace       = "namespace" Path "{" { NsItem } "}" ;
NsItem          = Namespace | [ "priv" ] Decl ;

                | FnDecl | ExternFn | ConstDecl | GlobalVar ) ;

Attribute       = "#[" Ident [ "(" ConstExpr ")" ] "]" ;

(* 構造体 *)
StructDecl      = "struct" Ident [ GenericParams ] [ ":" TypePath { "," TypePath } ]
                  "{" { StructItem } "}" ;
GenericParams   = "<" Ident { "," Ident } ">" ;
StructItem      = [ "priv" ] ( Field | { Attribute } ( FnDecl | ExternFn
                | StructDecl | EnumDecl | InterfaceDecl | TypeAlias | ConstDecl ) ) ;
Field           = Ident ":" Type [ "at" ConstExpr ] ";" ;

(* インターフェース *)
InterfaceDecl   = "interface" Ident "{" { "fn" Ident "(" SelfParam { "," Ident ":" Type } ")"
                  [ "->" Type ] ( ";" | Block ) } "}" ;

(* 列挙型 *)

EnumMember      = Ident [ "=" ConstExpr ] ;

(* 関数 *)

SelfParam       = [ "const" ] "self" ;

                  ( "at" ConstExpr | "from" StringLit ) ";" ;
ExternParams    = ExternParam { "," ExternParam } [ "," "..." ] | "..." ;
ExternParam     = SelfParam | Ident ":" Type | Type ;

Hook            = "hook" Path "(" [ Params ] ")" [ "->" Type ] Block ;

(* 変数・定数 *)
ConstDecl       = "const" Ident [ ":" Type ] "=" Expr ";" ;
GlobalVar       = ( "let" | "var" ) Ident [ ":" Type ] "=" Expr ";" ;

(* 型 *)
Type            = [ "const" ] [ "?" ] "*" Type
                | [ "const" ] [ "?" ] "*" "void"
                | "[" ConstExpr "]" Type
                | [ "const" ] "[" "]" Type
                | [ "?" ] "fn" "(" [ Type { "," Type } ] ")" [ "->" Type ]
                | TypePath ;

TypeSeg         = ( Ident | "Self" ) [ "<" Type { "," Type } ">" ] ;
Path            = [ "::" ] Ident { "::" Ident } ;

(* 文 *)

Stmt            = LetStmt | ConstDecl
                | AssignStmt | CallStmt
                | IfStmt | WhileStmt | LoopStmt | ForStmt | MatchStmt
                | "break" ";" | "continue" ";" | "return" [ Expr ] ";"
                | "delete" Expr ";"
                | "defer" ( CallStmt | AssignStmt | "delete" Expr ";" | Block )
                | Block ;

LetStmt         = ( "let" | "var" ) Ident [ ":" Type ] "=" Expr ";" ;
                                          (* orelse は Expr の一部として解析される *)

AssignOp        = "=" | "+=" | "-=" | "*=" | "/=" | "%="
                | "&=" | "|=" | "^=" | "<<=" | ">>=" ;

WhileStmt       = "while" Cond Block ;
LoopStmt        = "loop" Block ;
ForStmt         = "for" Ident "in" Expr [ ".." Expr ] Block ;

MatchArm        = Pattern { "," Pattern } "=>" Block ;
Pattern         = "_" | ConstExpr ;

OrExpr          = AndExpr { "||" AndExpr } ;
AndExpr         = CmpExpr { "&&" CmpExpr } ;

CmpOp           = "==" | "!=" | "<" | ">" | "<=" | ">=" ;

BitXorExpr      = BitAndExpr { "^" BitAndExpr } ;
BitAndExpr      = ShiftExpr { "&" ShiftExpr } ;
ShiftExpr       = AddExpr { ( "<<" | ">>" ) AddExpr } ;
AddExpr         = MulExpr { ( "+" | "-" ) MulExpr } ;
MulExpr         = CastExpr { ( "*" | "/" | "%" ) CastExpr } ;
CastExpr        = UnaryExpr { "as" Type } ;
UnaryExpr       = ( "-" | "!" | "~" | "&" ) UnaryExpr | NewExpr | PostfixExpr ;
NewExpr         = "new" Primary { PostfixOp } [ "?" { PostfixOp | "?" } ] ;
                                          (* 最初の "?" からは new の結果に掛かる *)
PostfixExpr     = Primary { PostfixOp | "?" } ;
PostfixOp       = "(" [ Args ] ")" | "[" Expr [ ".." Expr ] "]"
                | "." Ident | "->" Ident | ".*" ;
Args            = Expr { "," Expr } [ "," ] ;

Primary         = IntLit | FloatLit | CharLit | StringLit | WideStringLit
                | "true" | "false" | "null" | "self" | "original"

                | ArrayLit
                | "@" Ident "(" BuiltinArgs ")"
                | "(" Expr ")" ;

StructLitBody   = "{" [ FieldInit { "," FieldInit } [ "," ] ] "}" ;
FieldInit       = Ident ":" Expr ;
ArrayLit        = "[" ConstExpr "]" Type "{" [ Expr { "," Expr } [ "," ] ] "}" ;

CafeScript is a small language that is loaded into a program running on Wii U (PowerPC 750 family, 32-bit, big-endian) and compiled in place.

What CafeScript Is For

Its main uses are:

  • describing and reading/writing the memory layout of an existing process
  • calling or hooking functions of an existing process
  • providing functions and data to the host (the embedder)

Once the target process's classes and fields are declared with struct and extern fn, scripts are written like ordinary programs. Pointers are dereferenced explicitly, and values that may be null have type ?*T.

Design Principles

  • One way to do one thing. Do not provide multiple syntaxes for the same meaning.
  • Minimize implicitness. The only implicit conversions are a small fixed set. Conditions must be bool. Pointers are never dereferenced automatically.
  • The write target is visible in the syntax. If the assignment target goes through -> or .*, the write goes to the memory the pointer points to.
  • Express nullability in the type (?*T and *T).
  • Do not depend on declaration order. The meaning of a file is determined only by the file itself and the files it directly imports.
  • Introduce external facts in one place: the extern declaration. Hooks and calls refer to them by name.

Your First Script

This example declares a struct and a function of the target process and reads and writes through them.

#[size(0x0C)]
struct Vec3 {
    x: f32;
    y: f32;
    z: f32;
}

struct Actor {
    mPos: Vec3 at 0x10;
    mSpeed: f32 at 0x1C;

    extern fn GetActor(index: u32) -> ?*Actor at 0x02000000;
}

fn speedUp(step: f32) {
    for i in 0..8 {
        let actor = Actor::GetActor(i) orelse continue;
        actor->mSpeed += step;
    }
}
  • A field with at OFFSET reads and writes the memory at that offset.
  • extern fn ... at ADDR calls the function at that address.
  • -> dereferences a pointer. Extract a ?*T as *T with orelse and so on before using it.

0. Overview and Design Principles

CafeScript is a small compiled language that is loaded into a running program on Wii U (PowerPC 750 family, 32-bit, big-endian) and compiled in place. Its main uses are:

  • describing and reading/writing the memory layout of an existing process
  • calling or hooking functions of an existing process
  • providing functions and data to the host (the embedder)

Design Principles

  1. One way to do one thing. Do not provide multiple syntaxes for the same meaning.
  2. Minimize implicitness. The only implicit conversions are those in 14.1. Conditions must be bool. Pointers are never dereferenced automatically.
  3. The write target is visible in the syntax. If the assignment target goes through -> or .*, the assignment writes to the memory the pointer points to (13.4).
  4. Express nullability in the type (?*T and *T). The runtime representation is still the same as a C pointer, and it is never used as an optimization assumption.
  5. Do not depend on declaration order. The meaning of a file is determined only by the file itself and the files it directly imports.
  6. Introduce external facts in exactly one place: the extern declaration. Addresses and signatures appear only in extern declarations; hooks and calls refer to them by name.

1. Lexical Structure

1.1 Source

  • Source files are written in UTF-8. A BOM is ignored if present.
  • Line endings may be LF or CRLF. A newline is a kind of whitespace and has no grammatical meaning.
  • The file extension is .cafe.

1.2 Comments

// A comment to the end of the line
/* A block comment. /* These nest. */ */

1.3 Identifiers

identifier = (letter | "_") { letter | digit | "_" }
letter     = "A".."Z" | "a".."z"
digit      = "0".."9"
  • Only ASCII characters may be used in identifiers (non-ASCII characters are allowed only inside strings and comments).
  • Identifiers are case-sensitive.
  • A lone _ is not an identifier; it is reserved as the wildcard symbol (12.10).

1.4 Keywords

The following words are reserved and cannot be used as identifiers.

as        at        break     const     continue  defer     delete    else
enum      export    extern    false     fn        for       from      hook
if        import    in        interface let       loop      match     namespace
new       null      orelse    original  priv      return    self      Self
struct    true      type      use       var       void      while

Type names (such as i32) are not keywords. They are treated as names defined by the prelude (4.1).

1.5 Integer Literals

123        1_000_000
0x1100_0000   0X1F
0b1010_0101
0o755
  • _ may be placed between digits as a separator (not at the start, end, or immediately after a prefix).
  • The literal does not include a sign. -1 is a unary minus applied to a literal.
  • An integer literal is an untyped integer constant; its type is determined by context (13.2).

1.6 Floating-Point Literals

1.0    0.5    3.14159    1.0e-3    6.02E23    1_000.5
  • At least one digit is required before and after the decimal point (1. and .5 are invalid).
  • There are no type suffixes. The literal is an untyped floating-point constant whose type is determined by context (13.2).

1.7 Character Literals

'a'    '\n'    '\x41'
  • Only ASCII characters representable in one byte may be written. A character literal is treated as an untyped integer constant (its value is the character code).

1.8 String Literals

"hello"          // Type: const *u8 (cstr; UTF-8, NUL-terminated)
u"こんにちは"    // Type: const *u16 (wstr; UTF-16 BE, NUL-terminated)
  • The contents of "..." are placed as a UTF-8 byte sequence with one trailing 0.
  • The contents of u"..." are placed as UTF-16 (big-endian, surrogate pairs allowed) with one trailing 0.
  • The value of a string literal is the address of its first element, placed in read-only data, and is never null.
  • Literals with identical contents may be merged into the same address within one compilation.
  • A literal is a const pointer (4.2), so it cannot be written through. Writing through a pointer whose const was removed with as is undefined behavior (18).

2. Program Structure

2.1 Compilation Units

  • One compilation covers an entry file plus every file reachable from it through imports. This set is called a compilation unit.
  • In the host, one script is one compilation unit. Names from different compilation units do not interfere with each other.

2.2 File Layout

A file consists of a sequence of the following top-level items:

  • import declarations
  • use declarations
  • namespace blocks
  • declarations: struct, enum, type, fn, extern fn, const, var, let
  • hook declarations (entry file only)
  • modifiers on some of the above: export (entry file only), priv

Top-level items may appear in any order.

2.3 import

import "mc/client/Minecraft.cafe";
  • import adds the specified file to the compilation unit and makes its declarations referable from the file containing the import.
  • Paths are searched in this order, and the first existing file is used.
    1. Relative to the directory of the file containing the import
    2. The library roots supplied by the host or command line (in the order given)
  • The search never walks up parent directories.
  • The separator is /. Paths may contain ...
  • Importing the same file (the same normalized path) any number of times adds it to the compilation unit only once.
  • Imports may be cyclic.
  • Imports are not transitive. If A imports B and B imports C, A cannot refer to declarations in C by name (using them through a type is allowed; 3.6).
  • An import does not introduce names. Use use to shorten names.

2.4 namespace

namespace mc {
    struct Vec3 { ... }
}

namespace mc::entity {
    struct Entity { ... }
}
  • A namespace only determines the ownership of names; it has no runtime representation.
  • The same namespace may be opened in multiple files or in multiple blocks of the same file.
  • namespace a::b { } means the same as namespace a { namespace b { } }.
  • Inside a namespace, any top-level declaration except import, use, hook, and export may be written. import, use, hook, and export may appear only at the top level of a file, outside namespaces.
  • Declarations not in a namespace belong to the global namespace.

2.5 use

use mc::Minecraft;            // Makes Minecraft a short name for mc::Minecraft
use mc::entity as ent;        // Makes ent a short name for mc::entity
use mc::Vec3::ThreadStorage;  // Nested types are allowed
  • use P; introduces the last element of path P as a short name for what P denotes.
  • use P as N; introduces N as a short name for P.
  • P may denote a namespace, type, function, constant, or variable.
  • A short name is valid only within the file containing the use.
  • There is no wildcard import (*).
  • The target of use must be a declaration referable from that file (3.4).

2.6 Declaration Order

  • Top-level declarations may be referenced from positions before their declaration. There are no forward declarations.
  • A cycle in constant initializers or struct layout is an error (for example const A = B; const B = A; or struct S { s: S; }). Self-reference through a pointer (struct Node { next: ?*Node; }) is not a cycle.

2.7 export

export fn CreateModule() -> ?*Module { ... }
export const VERSION: u32 = 1;
export var gState: u32 = 0;
  • export emits a declaration as a symbol that the host can find by name.
  • It may be applied only to fn, const, and var at the top level of the entry file, outside namespaces.
  • An exported name becomes the symbol name as seen by the host.
  • An export const is emitted as a data symbol holding its value.
  • Declarations that are not exported are invisible to the host. If unused, they may be removed or inlined.

2.8 priv

priv const SECRET: u32 = 42;

struct Timer {
    priv elapsed: u32;
    fn tick(self) { ... }
}
  • A declaration, field, or method marked priv is referable only from the file that declares it.
  • priv is file-level visibility, not type-level.
  • A declaration without priv is referable from files that import its file.

3.1 Kinds of Names

Within a scope, a name denotes exactly one of the following:

  • a namespace
  • a type (struct, enum, type alias, or generic type parameter)
  • a function (fn, extern fn)
  • a constant (const)
  • a variable (var, let, parameter)
  • an enum member

There is no separate namespace for type names and value names. Within one scope, one name denotes exactly one entity.

3.2 Canonical Names

Namespaces, types, functions, constants, and global variables are identified by their canonical name (a path from the global namespace, such as mc::Vec3::ThreadStorage).

  • Two declarations with the same canonical name in one compilation unit are an error, except for namespaces (which may be reopened).
  • Declaring both a namespace and something else with the same canonical name (for example a namespace mc::Vec3 and a struct mc::Vec3) is an error.

3.3 Scopes

From innermost to outermost, the scopes are:

  1. Block (function body, the blocks of if / while / for / loop / match, and standalone blocks)
  2. Function parameters (and self)
  3. The associated scope of the enclosing struct (associated types, constants, functions, generic type parameters, and Self). Valid only from function bodies written inside that struct.
  4. Short names introduced by the file's use
  5. The enclosing namespaces (from inner to outer)
  6. The global namespace
  7. The prelude

Struct fields belong to none of these scopes. A field must always be accessed with an explicit receiver, such as self->x.

3.4 Referable Declarations

The declarations that file F can refer to, qualified or unqualified, are exactly:

  • declarations written in F itself
  • declarations written in files F directly imports, that are not priv
  • declarations in the prelude

The namespaces containing these declarations are the namespaces referable from F.

3.5 Unqualified Name Lookup

For an unqualified name N, the scopes in 3.3 are searched from innermost:

  • In scopes 1–3, the first match is used.
  • In scope 4, use short names are checked.
  • In scopes 5–7, each namespace is checked for a declaration of N that satisfies 3.4.

If no declaration is found, it is an error.

A local variable may shadow a same-named entity in an outer scope (a local variable in an outer block, a global declaration, and so on). Declaring the same name twice in one block is an error. Declaring a name in the outermost block of a function body that is the same as a parameter is also an error.

3.6 Qualified Names

A::B::C first resolves the leading A according to 3.5, then looks up each subsequent element inside the previous one. The right side of :: may be:

Left sideAllowed on the right
namespacedeclarations in that namespace satisfying 3.4
structassociated types, associated constants, functions (including methods with self; 8.6). Functions are also searched in base types (including ancestors)
enummembers

Writing ::A with a leading :: searches from the global namespace.

Use through a type: To use a field or method through -> or . on a value of some type, you do not need to import the file that declares that type. The 3.4 rules are required only when writing the name itself (type annotations, as, struct literals, Type::f(), hook, and so on).

4.2 Pointer Types

TypeMeaning

  • Size and alignment are both 4 for all of them (except pointers to interfaces; 5.9).

  • ? applies only to the single * immediately after it. ?*?*T means "a possibly-null pointer to a possibly-null pointer to T".
  • *void cannot be dereferenced, accessed as a member, used in pointer arithmetic, or indexed.

const

fn length(v: const *Vec3) -> f64 {
    return v->x * v->x + v->y * v->y;    // Reading is fine
    // v->x = 0.0;                       // Error: not a writable place

let n: u32 = 3;
let p = &n;                              // p: const *u32
  • const *T and const ?*T are pointers whose target cannot be written (a const pointer). They are distinct types from *T / ?*T but have the same representation. const may also be written on slices (const []T, 4.3) and pointers to interfaces (const *I / const ?*I, 5.9). Writing const before any other type is an error.
  • Places reached through a const pointer (p->f, p.*, p[i]) are not writable (13.4). Their addresses (&p->f) also become const pointers (13.13).
  • const applies only to the first level. A field q: *T read from p: const *S remains *T, and its target is writable (as with C const).
  • *T implicitly converts to const *T. The reverse implicit conversion does not exist (14.1). It can be removed with as (14.2), but writing through such a pointer to a non-writable place (a let variable, a parameter, a string literal) is undefined behavior (18).
  • A const pointer cannot be deleted (12.13).
  • Through a const pointer, only methods taking const self may be called (8.5).

4.3 Array Types

[16]u8
[4][4]f32      // An array of 4 elements (each element is [4]f32)
  • [N]T is a value type containing N copies of T. N is a constant expression (16) of integer type, greater than or equal to 0.
  • Its size is N * @sizeof(T) and its alignment is @alignof(T).
  • Arrays are values; assigning one copies it.
  • a.len is an untyped integer constant equal to the element count N.

Slice Types

[]u32
[]shared_ptr<Entity>
  • []T is a pair of "a pointer to the first element" and "an element count" (a slice). It is a value type with size 8 and alignment 4. Its layout is the same as ptr: ?*T at 0x0; len: u32 at 0x4;.
  • A slice does not own its elements. Keeping the elements alive is the programmer's responsibility.
  • s.len (u32) and s.ptr (?*T) read its contents. Neither is writable. To get a new range, create one with p[from..to] (13.6).
  • null implicitly converts to an empty slice (ptr null, len 0). The zero value is also an empty slice.
  • const []T is a slice whose elements cannot be written. s[i] is not writable, s.ptr is const ?*T, and s[i..j] is also const []T. []T implicitly converts to const []T (14.1). A slice created from a non-writable place or from a const pointer becomes const []T (13.6).
  • In a slice with 0 elements, ptr may be null. If the element count is 1 or more, ptr must not be null.
  • Slices cannot be compared with each other (test for emptiness with s.len == 0).

4.4 Function Types

fn(i32, f32) -> bool
fn(*Entity)          // No return value
?fn(*Entity)         // Possibly-null function pointer
  • A function type value is the address of a function. Its size and alignment are 4.
  • fn(...) is never null. A possibly-null function pointer is written ?fn(...).
  • Function types cannot have variadic arguments (...). Variadic arguments are available only in extern declarations (9.4).
  • Two function types are the same type if their parameter type lists and return types are all the same.

type EntityList = [64]?*Entity;
  • type N = T; makes N an alias for T. It does not create a new type (N and T are the same type).
  • Cyclic aliases are an error.
  • Type aliases cannot take generic arguments.

4.7 Prelude

Every file can refer to the following declarations (in a scope outside the global namespace).

// Basic types: i8 i16 i32 i64 u8 u16 u32 u64 f32 f64 bool
type cstr = const *u8;
type wstr = const *u16;

Declaring a name in the global namespace that is the same as a prelude name is an error.

4.8 Functions Without a Return Value

A function with no return value omits the return type. void is not a standalone type; it is allowed only inside *void and ?*void.

4.9 Type Identity

  • Basic types are identical by name.
  • Structs and enums are identical by canonical name (a generic struct is identical by its canonical name together with its type arguments).
  • Pointer, array, and function types are identical by structure.
  • Type aliases are identical by the type obtained after expanding the alias.

5. Structs

5.1 Declarations

struct Vec3 {
    x: f64;
    y: f64;
    z: f64;
}

#[size(0x58)]
struct Minecraft {
    mThePlayer: SharedPtr<MultiplayerLocalPlayer> at 0x104;
    mLevel: ?*MultiplayerLevel at 0x108;

    extern fn GetInstance() -> ?*Minecraft at 0x02001000;
}

A struct body may contain:

  • fields: [priv] name: Type [at OFFSET];
  • functions: fn, extern fn (8, 9)
  • associated types: struct, enum, interface, type
  • associated constants: const

5.2 Layout

Fields are placed in declaration order as follows.

  1. If at OFFSET is present, the offset is OFFSET (a constant expression). OFFSET must be a multiple of the field's alignment.
  2. Otherwise, the field is placed at the end of the previous field (offset + size), rounded up to a multiple of its alignment. The first field starts at 0 (or at the base size if there is inheritance).
  3. If two fields overlap, at least one of them must have an explicit at. Two implicitly placed fields never overlap. Overlap made with explicit at is allowed as an alias.

A struct's alignment is the maximum alignment of all fields (including inherited ones), or 1 if there are no fields.

A struct's size is the maximum end offset of all fields, rounded up to a multiple of the struct's alignment, or 0 if there are no fields.

#[size(N)] sets the size to N. If N is smaller than the computed size, or is not a multiple of the alignment, it is an error.

5.3 Inheritance

struct LivingEntity : Entity {
    mHealth: f32 at 0x1F4;
}
  • Only single inheritance is supported. The base must be a struct. After :, list the base struct (first, if present) and the interfaces to implement (5.9), separated by ,.
  • The base's fields are included from offset 0 with the same layout as the base.
  • In the derived struct, at offsets are measured from the start of the derived struct. Overlapping a base field is an error.
  • Declaring a field with the same name as one in the base (including ancestors) in the derived struct is an error.
  • A derived struct may declare a function with the same name as one in the base. This is hiding, and which one is called is determined by the receiver's static type (8.6). It is not a virtual call.
  • Using the same name for a field and a function is an error (including names inherited from a base).
  • *Derived implicitly converts to *Base (14.1).

5.4 Field Types

  • A field may have any type with a known size. Structs may be embedded by value, as may arrays and pointers.
  • A struct that contains itself by value (directly or indirectly) is an error.

5.5 Associated Declarations

struct Vec3 {
    struct ThreadStorage { ... }    // mc::Vec3::ThreadStorage
    enum Axis: i32 { X, Y, Z }      // Vec3::Axis::X
    const ZERO_LEN: f64 = 0.0;
    type Scalar = f64;
}
  • Associated declarations belong under the struct's canonical name.
  • From function bodies written inside the struct, they can be referred to without qualification (3.3).

5.6 Structs as Values

  • Structs are value types. Assignment, initialization, argument passing, and returns copy the whole value. However, a droppable type (8.11) can be copied only if it has a copy function, and that function is called.
  • == / != are not defined for structs (it is an error).
  • -> cannot be used on a struct value. Use ..

5.7 Struct Literals

let v = Vec3 { x: 1.0, y: 0.0, z: 0.0 };
var t = RepeatTimer { elapsed: 0, interval: 20, count: 0 };   // List inherited fields too
let z = Vec3 {};                                              // All fields zero
  • Type { name: expr, ... }. A trailing , may be omitted.
  • Fields may be listed in any order, but listing the same field twice is an error.
  • Omitted fields receive their zero value (15.5). Fields of a type without a zero value (*T, fn(...), and types containing them) cannot be omitted.
  • When fields are aliased with at, only one of the aliases may be specified in a literal. Specifying two aliases is an error.
  • A generic struct is written SharedPtr::<Player> { ... } (7.3).
  • To write a struct literal in the header of if / while / match / for (the expression immediately before {), enclose it in parentheses.

5.8 Array Literals

let a = [4]i32 { 1, 2, 3, 4 };
var buf = [16]u8 {};         // All elements zero
  • [N]T { e0, e1, ... }. If fewer than N elements are given, the rest are zero values (for a T without a zero value, elements cannot be omitted). More than N is an error.

5.9 Interfaces

interface Module {
    fn init(self);
    fn onTick(self);
    fn onEnable(self) {}                     // Default body
}

struct Counter : Module {
    ticks: u32;

    fn init(self) { self->ticks = 0; }
    fn onTick(self) { self->ticks += 1; }    // onEnable uses the default body
}

export fn CreateModule() -> ?*Module {
    return new Counter { ticks: 0 };         // ?*Counter -> ?*Module
}

fn Tick(m: *Module) { m->onTick(); }         // Counter::onTick is called
  • interface Name { fn name(self, ...) [-> T]; ... } declares a set of function names and types. A function takes self or const self (8.5) as its first parameter. Attributes cannot be applied. Interfaces cannot be generic.
  • A function may have a body (a default body). It is used when an implementing struct does not have a method with that name. Inside a default body, self has type *I, and the struct can be reached only by calling interface functions. Self cannot be used. A default body is type-checked and code-generated separately for each struct that uses it.
  • An interface is not a value type. Only *I and ?*I (pointers to an interface) may be used as values; using I itself as a variable, field, array element, or parameter type is an error.
  • A struct implements the interfaces listed after : (struct S : Base, I1, I2). For each interface function without a default body, the struct must have a method with the same name (found by the 8.6 lookup, including base methods). The parameter types after self and the return type must match the interface's. If the interface function is const self, the implementation must also be const self (a self function may implement either). The implementation may be an extern function, but not a variadic function, a drop function (8.11), or a priv function from another file. If the requirements are not met, the struct declaration is an error.
  • Implementations are not inherited. *S can be converted to *I only when S itself lists I.
  • *S / ?*S implicitly convert to *I / ?*I for interfaces S implements (14.1). The reverse conversion (*I to *S) does not exist.
  • p->m(args) (with p: *I) calls the method of the struct from which p was made (a dynamic call). For ?*I, first extract the value as with ?*T (15), then call.
  • const *I / const ?*I is a pointer to an interface through which only const self functions can be called. It can be made from *S / const *S, and *I implicitly converts to it (the reverse is impossible, even with as). Inside a default body of a const self function, self has type const *I.
  • On *I / ?*I, the only allowed operations are calling interface functions, assigning, initializing, passing as an argument, returning, storing into a field, comparing with null (?*I only), orelse, if let, while let, postfix ?, and delete (12.13). .*, field access, indexing, pointer arithmetic, conversion with as, and comparison between *I values are not allowed.
  • Representation: *I is two words (size 8, alignment 4), with a pointer to the struct at offset 0 and a pointer to a function table at offset 4. The table is an array containing the addresses of the functions declared by the interface in order, followed by a delete function, created once per struct/interface pair. The delete function does the same thing as delete on a pointer to that struct (12.13). Functions in the table are called with the pointer at offset 0 as self. When ?*I is null, offset 0 is 0 (the value at offset 4 is unspecified). Arguments and return values are handled as for struct values (19.2).

6. Enums

6.1 Declarations

enum Category: i8 {
    Combat,
    Item,
    Movement = 3,
    Render,          // 4
}
  • enum Name: IntType { Member [= expr], ... }. The underlying type IntType must be an integer type and cannot be omitted.
  • When = expr is omitted, the member's value is the previous member's value plus 1 (0 for the first member).
  • Values are constant expressions and must fit in the underlying type.
  • Multiple members may have the same value (aliases). Duplicate member names are an error.
  • Size and alignment are the same as the underlying type.

6.2 Usage

  • Members are written qualified by the type, such as Category::Movement.
  • An enum value may hold values other than its members (for example, a value read from game memory). Such values are valid values.
  • Conversion between an enum and an integer is explicit, using as (14.2).
  • Enums can be compared only with == and != (convert to integers with as for ordering comparisons).
  • Enums may be declared inside namespaces or structs.

7. Generics

7.1 Generic Structs

struct SharedPtr<T> {
    ptr: ?*T at 0x0;
    ctrl: ?*void at 0x4;

    #[inline]
    fn get(self) -> ?*T {
        return self->ptr;
    }
}

struct Pair<A, B> {
    first: A;
    second: B;
}
  • There must be at least one type parameter. Type parameter names enter the struct's associated scope (3.3).
  • Only structs can be generic. Functions, enums, and type aliases cannot take generic parameters (functions inside a struct may use that struct's type parameters).

7.2 Instantiation

  • Using a struct with type arguments, such as SharedPtr<Player>, creates that particular instantiation (monomorphization).
  • The same combination of type arguments is instantiated only once per compilation unit (identity is defined in 4.9).
  • There are no constraints on type arguments. The body is type-checked after instantiation. Errors report both the instantiation site and the body location.
  • If instantiation would continue forever (for example when using struct S<T> { x: ?*S<[2]T>; }), it becomes an error once a depth limit is exceeded. The limit is implementation-defined (at least 64).

7.3 Type Arguments in Expressions

In type positions (after :, after ->, after as, and inside type arguments), write SharedPtr<Player>.

In expressions, < is indistinguishable from the comparison operator, so type arguments are written ::<...>.

let p = SharedPtr::<Player> { ptr: null, ctrl: null };
let n = Pair::<i32, f32>::make(1, 2.0);

7.4 Self

Inside a struct, Self denotes that struct (for a generic struct, the instantiated type).

struct Node<T> {
    value: T;
    next: ?*Self;       // ?*Node<T>
}

8. Functions

8.1 Declarations

fn add(a: i32, b: i32) -> i32 {
    return a + b;
}

fn reset() {
    gTicks = 0;
}
  • fn name(params) [-> RetType] { body }.
  • Parameters are written name: Type. Parameters cannot be reassigned (they behave like let).
  • A function without a return type does not return a value.
  • There is no overloading (functions with the same name but different parameters).
  • There are no default arguments.
  • Recursion is allowed (except in #[inline] functions).

8.2 return and Return Values

  • In a function with a return value, control must not reach the end of the body (17). Every path must end with return expr;.
  • In a function without a return value, only return; may be written. Reaching the end returns from the function.

8.3 Parameter and Return Types

  • Parameters and return values may have any type with a known size. Structs and arrays may be passed by value (copied). The ABI is described in 19.2. Droppable types (8.11) cannot be parameters.

8.4 Attributes

#[inline]fnExpand the body at call sites. Recursion is not allowed. Taking the address also creates a separate, non-expanded body
#[deref]struct methodImplicitly call it where the struct's value is used as a pointer (8.8)
#[null]struct associated functionReturn the value of null written as that struct (8.9)
#[iter]struct methodImplicitly call it when iterating the struct's value with for (8.10)
#[drop]struct methodImplicitly call it when the struct's value is no longer needed (8.11)
#[copy]struct methodImplicitly call it when copying the struct's value (8.11)
  • Attributes are written immediately before the declaration. Unknown attributes are an error.
  • Inlining does not change meaning: arguments are evaluated exactly once each, from left to right.

8.5 Methods

struct Timer {
    elapsed: u32;
    interval: u32;

    fn tick(self) -> bool {
        self->elapsed += 1;
        if self->elapsed < self->interval { return false; }
        self->elapsed = 0;
        return true;
    }

    fn make(interval: u32) -> Timer {        // No self: associated function
        return Timer { elapsed: 0, interval: interval };
    }
}
  • A function inside a struct whose first parameter is self (with no type) is a method. The type of self is *Self (non-null).
  • Writing const self makes self have type const *Self, and the method cannot write to its struct. A const self method can be called on const pointers, non-writable places, and temporary values (8.6). It may also be written on extern functions (a promise that the declared function does not write; violating it is undefined, as in 9.2).
  • A function without self is an associated function.
  • self may appear only as the first parameter.

8.6 Calls

T::f(args)f is an associated function of struct TCall
T::m(p, args)m is a method of struct TPass p as self (p must convert to *T)

p->m(args)p: *I, m is a function of interface I. If p: const *I, m must take const selfCall the method of the struct from which p was made (5.9)

  • A method is looked up from the receiver's static type, through that struct, its bases, and their bases in order. The first match is used (hiding; 5.3).
  • When calling an ancestor's method, the receiver implicitly converts to the ancestor type.
  • Methods cannot be called on a ?*S receiver. Extract the value first (15).
  • If m does not take const self and v is a non-writable place (such as a let value), it is an error.
  • When passing a temporary value to a const self method, a droppable type (8.11) must be stored in a variable first.

8.7 Function Values

  • Writing a function name (f, T::f, T::m) without calling it yields a function-typed value.
  • The value of a method T::m has a function type in which self becomes a normal parameter of type *T.
  • Values of extern fn can also be taken. hook declarations and original cannot be taken as values.
  • For a const self method T::m, self becomes a parameter of type const *T in the function value's type.

8.8 Deref Function #[deref]

struct shared_ptr<T> {
    ptr: ?*T at 0x0;
    count: ?*void at 0x4;

    #[inline]
    #[deref]
    fn get(const self) -> ?*T { return self->ptr; }
}

let player = minecraft->mThePlayer orelse return;   // minecraft->mThePlayer.get() orelse return
if let target = minecraft->mTargetEntity { ... }    // if let target = minecraft->mTargetEntity.get()
  • A method marked #[deref] is a deref function. Its form must be fn name(self) -> ?*T or fn name(self) -> *T (where T is a struct).
  • When a struct S (or an ancestor) has a deref function, writing a value x of S in the following positions is treated as writing x.name():
    • x->f (13.5)
    • the left side of x orelse ... (13.14)
    • the expr of if let / while let (12.6, 12.7)
  • It is not converted in other positions (assignment, arguments, return, comparisons, and so on). Call it explicitly if needed.
  • Unlike v.m() in 8.6, x does not have to be a writable place. It may be a let variable or a function result. A value that is not a place is placed in temporary storage, and its address is passed. A non-writable place (let variable, parameter, place reached through a const pointer, or a field of one) is passed as const *S if the deref function takes const self; otherwise it is copied to temporary storage first. Therefore x itself is never modified.
  • If the deref function returns ?*T, x->f is an error (because it may be null, see 15). Extract it with orelse or if let first.
  • If a struct (including ancestors) has multiple deref functions, the first one found by the same lookup as 8.6 is used.
  • Comparing a struct value x that has a deref function with null using == / != is treated as x.name() == null.

8.9 Null-Value Function #[null]

struct shared_ptr<T> {
    ...
    #[inline]
    #[null]
    fn empty() -> Self { return Self { ptr: null, count: null }; }
}

fn GetPlayer() -> shared_ptr<Player> {
    let minecraft = Minecraft::GetInstance() orelse return null;   // shared_ptr::empty()
    return minecraft->mThePlayer;
}
var gTarget: shared_ptr<Entity> = null;
  • An associated function marked #[null] is a null-value function. Its form must be fn name() -> Self.
  • When a struct S has a null-value function, null implicitly converts to S and becomes that function's return value. Null-value functions of ancestors are not used.
  • If the body consists of a single return of a constant expression, that constant is used directly (the function is not called). It may also be used in a global variable initializer. Otherwise, the function is called for each conversion.
  • A null-value function's return value should be a value for which the deref function (8.8) returns null. The compiler does not check this.

8.10 Iteration Function #[iter]

struct vector<T> {
    start: ?*T at 0x4;
    finish: ?*T at 0x8;

    #[inline]
    #[iter]
    fn slice(const self) -> []T {
        let first = self->start orelse return null;
        let last = self->finish orelse return null;
        return first[0..(last - first) as u32];
    }
}

for it in level->mEntities { ... }   // it: *shared_ptr<Entity>
  • A method marked #[iter] is an iteration function. Its form must be fn name(self) -> []T (const self and const []T are also allowed).
  • If the x in for name in x (12.9) is a struct value with an iteration function, or a *S / const *S to such a struct, the iteration function is called once and the returned slice is iterated.
  • An iteration function is searched in the struct itself, then its base, then that base's base, and so on; the first match is used.
  • As with deref functions (8.8), x does not have to be a writable place, and self is passed by the same rules (a const *S x is treated as the non-writable place x.*).

8.11 Drop Function #[drop] and Copy Function #[copy]

struct shared_ptr<T> {
    ptr: ?*T at 0x0;
    count: ?*void at 0x4;

    #[drop]
    fn release(self) {
        ReleaseSharedCount(&self->count, false);
        self->ptr = null;
        self->count = null;
    }
}

fn Send(listener: *ClientPacketListener) {
    var packet: shared_ptr<Packet> = null;
    Packet::create(&packet);
    listener->send(&packet);
}   // packet.release() is called here
  • A method marked #[drop] is a drop function. Its form must be fn name(self) (const self is not allowed). A struct may have at most one.
  • The following types are droppable types:
    • a struct with a drop function
    • a struct with a droppable field, or with a droppable base
    • an array of a droppable type
  • Dropping a value means:
    • struct: call its own drop function (if any), drop its own fields in reverse declaration order, then drop the base
    • array: drop elements in order from the first
  • Dropping occurs in the following situations:
    • When a local variable (let / var) of a droppable type leaves its block. This happens whether the block is left by reaching the end, return, break, continue, or orelse return/break/continue; values are dropped from the most recently declared (also in reverse order with defer; 12.14). The return value is computed before dropping.
    • When assigning to a place of a droppable type. The right side is computed, then the old value is dropped, then the new value is written. This applies to local variables, global variables, and pointees alike.
    • When an expression statement discards a droppable value returned by a call. It is dropped immediately.
  • Global variables are never dropped (assignment drops only the old value).
  • Using an existing place (variable, field, .*, and so on) as the value of an initialization, assignment, return, struct literal, array literal, or new is called a copy. Copying a droppable value works as follows:
    • If the struct itself has a copy function (a method marked #[copy]), the copy is treated as x.name() and its return value is used. x does not have to be a writable place and is passed by the same rules as deref functions (8.8).
    • Otherwise it is an error. Copy functions of bases and fields are not used (the same applies to arrays).
    • Returning a local variable directly is a move, not a copy: the copy function is not called, and the variable is not dropped.
  • A droppable type cannot be passed by value. It cannot appear as a function parameter type either. Use *S.
  • A copy function's form must be fn name(self) -> Self (const self is also allowed). A struct may have at most one. It can be applied only to droppable types (other structs are copied bytewise). The returned value is treated as a new value and is dropped later. A copy function cannot copy the struct itself inside its own body (that would call itself forever). It may be called directly.
struct shared_ptr<T> {
    ...
    #[copy]
    fn retain(const self) -> Self {
        var out = Self { ptr: self->ptr, count: null };
        AcquireSharedCount(&out.count, &self->count);   // Increment the reference count
        return out;
    }
}

for it in level->mEntities {
    let entity = it.*;                     // entity = it.*.retain()
    let e = entity orelse continue;
    ...
}                                          // entity is dropped, decrementing the count
  • A temporary value such as a call result cannot be used directly with ->, ., indexing, ?, orelse, if let, or for. Store it in a variable first (so that it is not dropped while in use).
  • When a struct literal or array literal contains values of droppable types, orelse return/break/continue (including the block form) cannot be used inside it. Leaving early would leave a partially built value undropped. Compute the values with let first.
  • A drop function cannot be called directly. To release a value early, assign another value such as null.
  • A field of a droppable type cannot share memory with another field.
  • If a function to which &x was passed overwrites a droppable value, the old value is not dropped. Pass an empty value (such as null) to such functions.

8.12 Constructors and Destructors

struct Note {
    count: i32;

    fn make(count: i32) -> Self { return Self { count: count }; }
}

let a = Note::make(1);                        // Create on the stack
let p = new Note::make(2) orelse return;      // Create on the heap (13.17)
defer delete p;

struct Zombie : Monster {
    extern fn __ct(ptr: ?*Self, level: ?*Level) -> ?*Self at 0x02003000;
    extern fn __dt(self, disposing: bool) at 0x02003010;
}

let z = Zombie::__ct(null, level) orelse return;   // The game's constructor
defer z->__dt(true);                                // The game's destructor
  • The language has no constructor or destructor mechanism. By convention, an associated function returning Self by value is called a constructor; its name is arbitrary.
  • The implementation calls neither constructors nor destructors implicitly (including base ones). Building and destroying the base part is the responsibility of the type's author. Only drop functions and copy functions (8.11) are called implicitly.
  • Game (GHS) constructors are declared as ordinary extern functions. If ptr is null, the constructor allocates its own size with the game's operator new (returning null on failure); if ptr is not null, it uses the memory pointed to by ptr. It then calls the base constructors itself before building its own part. Calling it on an already-built object initializes it twice, so call it only on free memory.
  • Game destructors (__dt and so on) are also ordinary extern functions and are called manually. Neither delete nor the end of a scope calls them. A GHS destructor frees memory too when disposing is true.

9. extern Declarations

9.1 Syntax

// Function at a fixed address
extern fn GetInstance() -> ?*Minecraft at 0x02001000;

// Function provided by the host under a name
extern fn Notify(module: cstr, message: cstr) -> u32 from "host";

// Inside a struct: methods (with self) and associated functions (without self)
struct Vec3 {
    extern fn length(self) -> f64 at 0x02005000;
    extern fn newTemp(x: f64, y: f64, z: f64) -> *Vec3 at 0x02006000;
}
  • extern fn name(params) [-> RetType] LOCATION;
  • LOCATION is one of:
    • at ADDR: ADDR is an untyped integer constant or a constant expression of type u32. It denotes a fixed address.
    • from "PROVIDER": at load time, the host resolves the pair of provider PROVIDER and function name name. The provider "cafe" is reserved for the implementation's runtime helpers; writing it is an error.
  • An extern declaration has no body.

9.2 Meaning

  • An extern function is called like an ordinary function (8.6).
  • Calls follow the calling convention in 19.
  • If the host cannot resolve a from function, loading fails (the host reports an error).
  • The compiler cannot check that an extern declaration's address and signature match the actual implementation. If they do not match, behavior is undefined (18).

9.3 Parameter Names

Parameter names may be omitted in extern declarations.

extern fn set(self, f64, f64, f64) at 0x02006010;

9.4 Variadic Arguments

extern fn OSReport(fmt: cstr, ...) at 0x0123_4567;
  • ... may be written at the end of the parameter list. Actual arguments passed for ... follow these rules:
    • Untyped integer constants are treated as i32, and untyped floating-point constants as f64.
    • f32 is promoted to f64.
    • bool, i8, i16, u8, and u16 are promoted to i32 / u32.
    • Struct and array values cannot be passed.
  • An extern function with variadic arguments cannot be taken as a value (4.4).

9.5 const Parameters

struct MultiPlayerGameMode {
    extern fn attack(self, player: const *shared_ptr<Player>, entity: const *shared_ptr<Entity>) at 0x02002000;
}
struct Mob {
    extern fn getTarget(self, result: *shared_ptr<LivingEntity>) at 0x02004000;   // Writes through the parameter
}

gameMode->attack(&minecraft->mThePlayer, it);   // *shared_ptr<MultiplayerLocalPlayer> can be passed
mob->getTarget(&zombie);                        // Error: a LivingEntity could be written into shared_ptr<Zombie>
  • C++ by-value and const& parameters are declared as const-pointer parameters (4.2). Because the body of an extern function cannot be checked, const is a promise that the declared function does not write. If a function declared with const does write through the parameter, behavior is undefined (the same declaration/implementation mismatch as 9.2).
  • A const pointer may also be converted to read memory as another type (14.1, item 6). This is why a shared_ptr<MultiplayerLocalPlayer> can be passed to const *shared_ptr<Player>. This conversion is not allowed for non-const parameters, because the function could write a value of the other type (just as C++ cannot pass a converted temporary to a non-const reference).

10. hook Declarations

10.1 Syntax

hook mc::Entity::tick(self) {
    original(self);
    self->mMotion.y += 0.01;
}

hook mc::Gui::render(self, partialTicks: f32) {
    original(self, partialTicks);
    drawOverlay();
}
  • hook PATH(params) [-> RetType] { body }
  • PATH must denote an extern function declared with at (functions declared with from cannot be hooked).
  • The parameter type list and return type must match the extern declaration exactly (including const). Parameter names are arbitrary (self is required for methods, and must be written const self if the extern declaration uses const self).
  • A hook declaration may appear only at the top level of the entry file (outside namespaces).
  • Declaring two hooks for the same extern function in one compilation unit is an error.

10.2 original

  • Inside a hook body, original denotes the original implementation of the hooked function (the next function in the host's hook chain).
  • The parameters and return value of original(args) are the same as in the extern declaration.
  • original may be called zero or more times.
  • original cannot be used outside a hook body, and cannot be taken as a value.

10.3 Meaning

  • A hook is registered with the host, which patches the target address. How patching is done and how multiple hooks on the same address are chained is the host's responsibility.
  • Which thread calls a hooked function is determined by the game. It may run concurrently with other script functions (18).

12.3 Assignment

place = expr;

  • The left side must be a writable place (13.4).
  • Assignment is a statement, not an expression (it has no value).
  • Evaluation order: evaluate the subexpressions that determine the left-side place from left to right, then evaluate the right side, and finally store.
  • place op= expr has the same meaning as place = place op expr, but the subexpressions that determine place are evaluated only once.
  • There is no ++ or --.

  • The only expression that may be written as a statement is a function call. The return value may be discarded.
  • Writing any other expression as a statement (x + 1;, null;, and so on) is an error.

12.5 if

if a > b {
    ...
} else if a == b {
    ...
} else {
    ...
}
  • The condition must have type bool. Parentheses around the condition are not required.
  • The body must be a block.

12.6 if let

if let p = gTarget {
    p->mGlowing = true;       // p: *Entity
} else {
    ...
}
  • if let name = expr { } [else ...]
  • expr must have type ?*T (or ?fn(...)). If it is a struct value with a deref function, the result of calling that function is used (8.8).
  • If expr is not null, bind name as a let variable of type *T (or fn(...)) and run the first block. If it is null, run else.
  • name is valid only inside the first block.
  • else if let ... may also be written.

12.7 while and while let

while i < 10 {
    i += 1;
}

var node = list->head;           // ?*Node
while let n = node {
    total += n->value;
    node = n->next;
}
  • while cond { }: cond must be bool.
  • while let name = expr { }: evaluate expr each time; if it is not null, bind it and run the body. If it is null, stop.

12.8 loop

loop {
    if done() { break; }
}
  • An infinite loop. Exit with break.

12.9 for

for i in 0..10 { ... }                       // i: i32, 0 through 9
for i in 0..buf.len { buf[i] = 0; }
for it in v->begin..v->end { ... }           // it: *T, advances by element size
for it in slice { ... }                      // it: *T, each element of the slice
for it in gArray { it.* = 0; }               // it: *T, each element of the array
for it in level->mEntities { ... }           // Each element of the slice returned by the iteration function (8.10)

Range for

  • for name in a..b { }
  • a and b must have the same integer type, or the same pointer type *T (if one is an untyped constant, it takes the other's type; if both are untyped constants, they are i32; if one can be implicitly converted to the other's type, that type is used).
  • a and b are evaluated once each, from left to right, before the loop starts.
  • name is bound as a let on each iteration, with the values a, a+1, …, b-1 (for pointers, advancing one element at a time). If a >= b, the body does not run at all.
  • In an integer range, computing b-1 does not overflow even when b is the minimum value of the type. The loop continues while "the current value < b".

Element for

  • for name in x { } (the form without ..). x must be one of:
    • a slice []T / const []T
    • an array [N]T. A temporary array is placed on the stack.
    • a struct S with an iteration function, or *S / const *S (8.10)
  • x is evaluated exactly once before the loop starts (the iteration function is also called only once).
  • name is bound as a let of type *T and points to each element. To modify an element, write to name.* or name->f. For const []T and non-writable arrays (such as arrays declared with let), name has type const *T.
  • An empty slice (len 0) runs the body zero times. If the element count of the original container changes during the loop, behavior is unspecified (the range from the start is iterated).

12.10 match

match lang {
    Language::Japanese => { ... }
    Language::English, Language::French => { ... }
    _ => { }
}

match gTicks {
    180 => { ... }
    360 => { ... }
    _ => { }
}
  • The target expression must be an integer type, an enum type, or bool.
  • Each arm is pattern [, pattern ...] => { block }. The arm body must be a block, and no , is written after an arm.
  • A pattern is a constant expression of the target's type (enum members are also allowed) or _ (wildcard).
  • The same value may not appear in two patterns. _ may appear only as the last arm, alone.
  • The target expression is evaluated once. Arms are tested from top to bottom and the first match runs. There is no fallthrough.
  • Exhaustiveness:
    • bool: both true and false must be present, or _ is required.
    • integer types: _ is required.
    • enums: _ may be omitted only when all members are listed. Even then, values other than members (6.2) match no arm and nothing is executed.

12.11 break / continue

  • break; exits the innermost while / while let / loop / for.
  • continue; proceeds to the next iteration of the innermost loop (for for, the next value).
  • There are no labeled break / continue.
  • Using them outside a loop is an error.

12.12 return

  • return expr; (in a function with a return value), return; (in a function without one).

12.13 delete

let note = new Note { count: 1 } orelse return;
note->count += 1;
delete note;
  • delete expr;. expr must be *T or ?*T (T is a type with a known size; *void is not allowed), or *I / ?*I (5.9). Const pointers (4.2) are not allowed.
  • For *I, perform the same operation for the struct type T from which it was created (call the delete function from the function table).
  • expr is evaluated only once. If it is null, nothing happens. Otherwise, drop the pointed-to value as the static type T of expr (8.11), then return the memory to the allocator used by new.
  • It may be used only on memory created by new from a value (13.17). Using it on any other pointer, or on an already-deleted pointer, is undefined behavior (18.1).
  • T must be the same as the type of the value created by new. Deleting a derived value through a base pointer is undefined behavior (derived fields are not dropped; there is no virtual destructor).
  • It does not call the game's destructor (8.12). Game objects are destroyed by calling their destructor manually.
  • delete does not change the pointer's value.

12.14 defer

fn Spawn(level: *Level) {
    let z = Zombie::__ct(null, level) orelse return;
    defer z->__dt(true);           // Runs last no matter how the function exits

    let note = new Note::make(1) orelse return;   // z is destroyed even if we return here
    defer delete note;

    if !setup(z) { return; }       // Cleanup runs in the order note, then z
    defer {
        log("done");
        gCount += 1;
    }
}
  • defer statement. The statement may be a call, assignment, delete, or a block { ... }.
  • A defer is registered when execution reaches it and runs when the enclosing block is left. The exit path does not matter (end of block, return, break, continue, including orelse return/break/continue). A defer that is never reached does not run.
  • Execution order is the reverse of registration, also forming a reverse order with local variable drops (8.11). Therefore, a variable declared before a defer is dropped after that defer runs and can be used safely inside it.
  • Names are resolved at the position of the defer statement.
  • The expr of return expr; is computed before running defers.
  • Control cannot leave a defer (a return, a break / continue targeting a loop outside the defer, or orelse return/break/continue is an error). break / continue for a loop inside the defer are allowed.
  • A defer inside a defer runs when the block inside the outer defer is left (just like an ordinary block).

13.2 Untyped Constants

  • Integer literals, character literals, floating-point literals, const declarations without a type annotation, and constant expressions made only from them are untyped constants.
  • An untyped constant is converted to the type of the context in which it is used (assignment target, argument, the other operand, and so on).

13.4 Places and Writability

A place is an expression that denotes a location in memory. The following are places:

  • a variable (let, var, parameters; self is excluded, since self is a value)
  • p->f (where p is an expression of type *T)
  • x.f (where x is a place holding a struct value)
  • p.* (where p is an expression of type *T)
  • a[i] (where a is a place holding an array, or an expression of type *T)
  • s[i] (where s is a slice)

Whether a place is writable is determined as follows:

  • A variable declared with var is writable. Variables declared with let and parameters are not writable.
  • p->f, p.*, p[i] (where p is a pointer), and s[i] (where s is a slice) are writable unless p / s is const (a place reached through a dereference). If const, they are not writable.
  • x.f and x[i] (where x is a value) are writable only when x is writable.

Write-target rule: If a writable place goes through a dereference (->, .*, or indexing a pointer), the write is to the memory the pointer points to. Otherwise, the write is to the script's own variable (a local or global variable).

13.7 Arithmetic

+ - * / % require both operands to have the same numeric type (untyped constants adapt to the other operand's type). There is no implicit widening (i32 + i64, f32 + f64 are errors).

Integers

  • Results wrap around using two's complement in the result type (overflow is not an error).
  • / truncates toward zero. The sign of % follows the left operand (a == (a / b) * b + a % b).
  • Division by zero, and dividing the minimum signed value by -1, have unspecified results (they do not trap; 18).

Floating point

  • Follows IEEE 754. f32 operations are performed in single precision and f64 operations in double precision.
  • % cannot be used on floating-point numbers.

Unary -

  • Applies to numeric types. For unsigned integers it is the two's complement (0 - x).

13.9 Comparisons

  • == and !=: both sides must have the same type (after implicit conversions) and be numeric, bool, enum, pointer, or function type. ?*T can be compared with null. *T cannot be compared with null (because *T is the non-null type; 15.3).
  • < > <= >=: both sides must have the same numeric type, or the same pointer type *T (addresses are compared as unsigned).
  • The result is bool.
  • Floating-point comparisons follow IEEE 754 (NaN compares false to everything except !=).
  • Structs and arrays cannot be compared.
  • ?*I (a pointer to an interface) can be compared only with null (5.9).

13.10 Logical Operations

  • The operands of !x, x && y, and x || y must be bool. The result is bool.
  • && and || short-circuit (the right side is not evaluated if the left already determines the result).

13.11 Bitwise Operations and Shifts

  • & | ^ require both sides to have the same integer type. ~x requires an integer type.
  • << and >> require an integer left side. The right side may have any integer type (it need not match the left side). The result has the left side's type.
    • >> is an arithmetic shift for signed integers and a logical shift for unsigned integers.
    • The result is unspecified if the shift amount is negative or at least the bit width of the left side's type.
  • Bitwise operations cannot be used on bool.

Postfix ? (Forced Unwrap)

let player = minecraft->mThePlayer orelse return;          // Use orelse for values that may be null

  • If x is null, it traps immediately (the tweqi instruction). Execution does not continue, and the exception handler's SRR0 points to that ?.
  • Do not use it for values that can be null (such as mThePlayer on the title screen); use orelse or if let.
  • Because it is a postfix operator, it can be chained as a?->b?->c. Parentheses are needed to apply it to the result of as ((x as ?*T)?).

13.16 Evaluation Order

  • Operands of binary operators, actual arguments of function calls (including the receiver), and elements of struct and array literals are evaluated from left to right in the order written.
  • The expression denoting the called function (such as a function pointer expression) is evaluated before the actual arguments.
  • &&, ||, and orelse follow 13.10 and 13.14.
  • The expr of new expr is evaluated after memory is allocated (13.17).

13.17 new

let note = new Note { count: 1, pos: v } orelse return;   // ?*Note
let other = new Note::make(2) orelse return;              // Write the constructor's result directly (8.12)
  • new expr allocates @sizeof(T) bytes (1 if 0), evaluates expr only if allocation succeeds, and writes the result directly into that memory. The result is ?*T, or null if allocation fails. T is the type of expr (untyped constants use their default type from 13.2).
  • If expr is a call returning a value, the allocated memory is passed as the return-value area and written directly (no copy). Fields omitted from a struct literal become zero values. Nothing else is called (8.12).
  • If T is a pointer or function type, it is an error. Functions returning pointers (such as game constructors) allocate their own memory, so call them without new.
  • Writing a droppable value (8.11) from an existing place (such as a variable) makes a copy (an error if there is no copy function).
  • orelse return/break/continue (including the block form) cannot be used inside expr. Leaving early would leak the allocated memory.
  • Discarding the result of new is an error (it cannot be an expression statement).
  • Allocated memory is not freed automatically, and the value in it is not dropped. Free it with delete (12.13).
  • The ? in new x? applies to the result of new (the same as (new x)?).
  • Memory is allocated and freed with the runtime helpers __cs_alloc / __cs_free from provider "cafe". __cs_alloc(size: u32) -> ?*void returns 8-byte aligned memory, or null if allocation fails.

  • 4 applies only to a single level of pointer. It does not change the type behind the pointer, as in *?*Derived to *?*Base (because ?*Base could then be written through). Item 6, where the pointee is not writable, can change the pointee's type under the following conditions.
  • In item 6, "the memory of A can be read as B" means one of the following. For slices, the sizes of A and B must also be equal.
    • A is the same as B, or a struct that has B as an ancestor.
    • A and B are pointers, and A can be converted to B by a conversion in this section (such as reading ?*Derived as ?*Base).
    • A and B are instantiations of the same generic struct, have a deref function (8.8), have the same size, bases, and offsets for all fields, and each field's type satisfies this condition (for example reading shared_ptr<MultiplayerLocalPlayer> as shared_ptr<Player>). Structs with a deref function are treated as pointing to one object; structs that can point to an array (such as vector<T>) are excluded.
  • A stored pointer is converted only one level (*?*?*Derived cannot be converted to const *?*?*Base). Even if the pointee memory is not writable, the memory pointed to by the pointer stored there is writable.
  • Implicit conversions occur for assignment, initialization, argument passing, return values, matching the other operand's type in a binary operation, and the right side of orelse.

Bit reinterpretation (for example f32 ↔ u32) is done with @bitcast (13.12), not as. Conversely, pointers and function types cannot be converted with @bitcast; use as (so that null checks cannot be bypassed with @bitcast).

15. Null Safety

15.1 Principle

  • A value that may be null is represented by ?*T (?fn(...)).
  • A ?*T value may be freely assigned, compared, passed as an argument, returned, and stored in a field.
  • Before dereferencing a ?*T value (->, .*, indexing, method calls, function calls), it must first be extracted as *T. There are exactly four ways to extract:
    • orelse (13.14)
    • if let (12.6)
    • while let (12.7)
    • postfix ? (13.14; traps if null)

15.2 No Type Narrowing

Even inside if p != null { ... }, the type of p remains ?*T. The result of a comparison is never used to change a type.

15.3 Not an Optimization Assumption

The compiler must not use the fact that a *T value is non-null as an optimization assumption. The distinction between *T and ?*T exists only for type checking and does not affect generated code.

Therefore, even if an external declaration is wrong and a *T holds 0, a comparison such as (p as ?*T) == null is still executed rather than optimized away (*T cannot be compared directly with null; 13.9).

15.4 Paths That Can Put Null in *T

A *T may receive 0 through the following paths. These are outside the type system and are the responsibility of the programmer (or the binding generator):

  • the return value or parameter types of an extern declaration do not match the implementation (9.2)
  • a pointer field declared *T in a struct describing game memory actually receives null
  • as between pointers misinterprets the memory being pointed to
  • pointer arithmetic produces address 0

Binding generation rule (recommended): Pointers originating from external memory or functions should default to ?*T. Use *T only for pointers confirmed never to be null (such as functions returning this).

15.5 Zero Values

16. Constant Expressions

A constant expression is an expression whose value is determined at compile time or by relocation at load time. Constant expressions are required in:

  • the initializer of a const
  • the initializer of a global variable
  • the offset or address in at, #[size(N)], array element counts, and enum member values
  • match patterns

Only the following may appear in a constant expression:

  • literals, true, false, null
  • const declarations, enum members
  • unary and binary operators (including && and ||), as (between numeric types, for enums, and from an integer to a pointer)
  • @sizeof, @alignof, @offsetof, @bitcast
  • struct literals and array literals (all elements must be constant expressions)
  • values determined by relocation (only in the initializers of global variables and const)
    • string literals
    • function names (function values)
    • &g, &g.f, &g[i] (g is a var global variable; i is a constant expression)
    • values converted to *I / ?*I by an implicit conversion (14.1)

Values determined by relocation cannot be operands of an operation (they may only be stored as-is). However, p + n (where n is a constant expression) is allowed.

Values determined by relocation cannot be used in at, #[size], array element counts, enum values, or match patterns (those require a value known at compile time).

17. Reachability

Whether the end of a function (8.2) or the end of an orelse block (13.14) can be reached is determined only by the following rules. No value analysis is performed (code after if true { return; } is still considered reachable).

A statement S cannot reach the end in these cases (defer statements do nothing at their position, so they always reach the end):

  • return, break, continue
  • a block whose last statement cannot reach the end
  • an if with an else where every branch cannot reach the end (likewise for if let)
  • a loop whose body contains no break targeting that loop
  • a match with a _ arm (or an exhaustive set of arms) where every arm cannot reach the end

Inside a block, a statement after one that cannot reach the end produces a warning (unreachable code).

18. Undefined and Unspecified Behavior

18.1 Undefined Behavior

In the following cases, program behavior is undefined (it may crash, corrupt game memory, and so on):

  • dereferencing an invalid address (including 0, and including when a *T contains 0)
  • accessing outside the bounds of an array or pointer
  • reading or writing memory whose type does not match reality (for example, converting to the wrong type with as)
  • the address or signature of an extern declaration not matching the implementation
  • multiple threads writing (or reading and writing) the same memory concurrently without synchronization
  • recursion deep enough to overflow the stack in a non-#[inline] function
  • calling delete on a pointer not created by new from a value, or on an already-deleted pointer; accessing deleted memory
  • writing through a pointer whose const was removed with as (4.2) to a non-writable place (a let variable, a parameter, a string literal); writing through a pointer made const with the item-6 conversion of 14.1 to memory viewed as another type after removing const with as
  • a const parameter (9.5) or a const self extern function actually writing through it

18.2 Unspecified Behavior

In the following cases the resulting value is unspecified, but it does not trap and does not affect other parts of the program:

  • integer division by zero, or the minimum signed value divided by -1 (/ and %)
  • a shift amount that is negative or at least the left operand's bit width
  • conversion from floating point to integer when out of range or NaN
  • p - q when the difference is not divisible by the element size

18.3 Implementation-Defined

  • how library roots are specified
  • the depth limit for generic instantiation (at least 64)
  • the names of internal symbols in the output

19. ABI and Code Generation

19.1 Target

  • PowerPC 32-bit, big-endian (Wii U Espresso)
  • The calling convention follows the PowerPC EABI (SVR4 ABI) so that functions can interoperate with the game (GHS compiler).

19.2 Calling Convention

19.3 Call Generation

  • Calls to extern functions declared with at, extern functions declared with from, calls through function pointers, and calls to interface functions (addresses read from the function table) load the address into ctr and execute bctrl.
  • Calls between functions within a script may use a relative branch (bl).

19.4 Output

The compiled result includes at least:

  • a code area (.text)
  • a read-only data area (string literals, top-level let)
  • a writable data area (global variables, export const data symbols)
  • relocation information (addresses in data, function addresses, resolution targets of from externs)
  • a list of exported symbols (name, kind, offset)
  • a list of hooks (target address, offset of the hook body, offset of the location holding the original value)

Before enabling a hook, the host writes the address of the next function in the hook chain into the location holding original.

19.5 Internal Symbols

The implementation chooses the symbol names of non-exported declarations from their canonical names and defining files. Identically named declarations in different files or namespaces never collide in the output.

20. Diagnostics

20.1 Errors

Everything this specification calls an "error" is a compile error, and no compiled output is produced.

Error messages include the file, line, and column. Errors originating from generic instantiation also show the instantiation site.

20.2 Required Warnings

  • orelse null (13.14)
  • unreachable code (17)
  • lost writes to a copy: when a struct or array value is copied with let / var into a place that does not go through a dereference (a variable of the script itself), a field or element of that copy is written, and then the variable is never read before leaving its scope. This warns that the programmer may think they modified game memory but actually modified a copy.
var abilities = player->mAbilities;   // Copy
abilities.mFlying = true;             // Warning: abilities is never read afterwards
  • unused local variables (names beginning with _ are excluded)

21. Grammar (EBNF)

Notation: { X } is zero or more repetitions, [ X ] is optional, | is alternation, and "..." is a token.

File            = { TopItem } ;

TopItem         = Import | Use | Namespace | Hook
                | [ "export" ] Decl
                | [ "priv" ] Decl ;

Import          = "import" StringLit ";" ;
Use             = "use" Path [ "as" Ident ] ";" ;
Namespace       = "namespace" Path "{" { NsItem } "}" ;
NsItem          = Namespace | [ "priv" ] Decl ;

Decl            = { Attribute } ( StructDecl | EnumDecl | InterfaceDecl | TypeAlias
                | FnDecl | ExternFn | ConstDecl | GlobalVar ) ;

Attribute       = "#[" Ident [ "(" ConstExpr ")" ] "]" ;

(* Structs *)
StructDecl      = "struct" Ident [ GenericParams ] [ ":" TypePath { "," TypePath } ]
                  "{" { StructItem } "}" ;
GenericParams   = "<" Ident { "," Ident } ">" ;
StructItem      = [ "priv" ] ( Field | { Attribute } ( FnDecl | ExternFn
                | StructDecl | EnumDecl | InterfaceDecl | TypeAlias | ConstDecl ) ) ;
Field           = Ident ":" Type [ "at" ConstExpr ] ";" ;

(* Interfaces *)
InterfaceDecl   = "interface" Ident "{" { "fn" Ident "(" SelfParam { "," Ident ":" Type } ")"
                  [ "->" Type ] ( ";" | Block ) } "}" ;

(* Enums *)
EnumDecl        = "enum" Ident ":" Type "{" [ EnumMember { "," EnumMember } [ "," ] ] "}" ;
EnumMember      = Ident [ "=" ConstExpr ] ;

TypeAlias       = "type" Ident "=" Type ";" ;

(* Functions *)
FnDecl          = "fn" Ident "(" [ Params ] ")" [ "->" Type ] Block ;
Params          = Param { "," Param } ;
Param           = SelfParam | Ident ":" Type ;
SelfParam       = [ "const" ] "self" ;

ExternFn        = "extern" "fn" Ident "(" [ ExternParams ] ")" [ "->" Type ]
                  ( "at" ConstExpr | "from" StringLit ) ";" ;
ExternParams    = ExternParam { "," ExternParam } [ "," "..." ] | "..." ;
ExternParam     = SelfParam | Ident ":" Type | Type ;

Hook            = "hook" Path "(" [ Params ] ")" [ "->" Type ] Block ;

(* Variables and constants *)
ConstDecl       = "const" Ident [ ":" Type ] "=" Expr ";" ;
GlobalVar       = ( "let" | "var" ) Ident [ ":" Type ] "=" Expr ";" ;

(* Types *)
Type            = [ "const" ] [ "?" ] "*" Type
                | [ "const" ] [ "?" ] "*" "void"
                | "[" ConstExpr "]" Type
                | [ "const" ] "[" "]" Type
                | [ "?" ] "fn" "(" [ Type { "," Type } ] ")" [ "->" Type ]
                | TypePath ;
TypePath        = [ "::" ] TypeSeg { "::" TypeSeg } ;
TypeSeg         = ( Ident | "Self" ) [ "<" Type { "," Type } ">" ] ;
Path            = [ "::" ] Ident { "::" Ident } ;

(* Statements *)
Block           = "{" { Stmt } "}" ;
Stmt            = LetStmt | ConstDecl
                | AssignStmt | CallStmt
                | IfStmt | WhileStmt | LoopStmt | ForStmt | MatchStmt
                | "break" ";" | "continue" ";" | "return" [ Expr ] ";"
                | "delete" Expr ";"
                | "defer" ( CallStmt | AssignStmt | "delete" Expr ";" | Block )
                | Block ;

LetStmt         = ( "let" | "var" ) Ident [ ":" Type ] "=" Expr ";" ;
                                          (* orelse is parsed as part of Expr *)
AssignStmt      = Expr AssignOp Expr ";" ;
AssignOp        = "=" | "+=" | "-=" | "*=" | "/=" | "%="
                | "&=" | "|=" | "^=" | "<<=" | ">>=" ;
CallStmt        = Expr ";" ;              (* Expr must be a call expression *)

IfStmt          = "if" Cond Block [ "else" ( IfStmt | Block ) ] ;
Cond            = Expr | "let" Ident "=" Expr ;
WhileStmt       = "while" Cond Block ;
LoopStmt        = "loop" Block ;
ForStmt         = "for" Ident "in" Expr [ ".." Expr ] Block ;
MatchStmt       = "match" Expr "{" { MatchArm } "}" ;
MatchArm        = Pattern { "," Pattern } "=>" Block ;
Pattern         = "_" | ConstExpr ;

(* Expressions (precedence in 13.1) *)
Expr            = OrElseExpr ;
OrElseExpr      = OrExpr [ "orelse" OrElseRhs ] ;
OrElseRhs       = "return" [ Expr ] | "break" | "continue" | Block | OrElseExpr ;
OrExpr          = AndExpr { "||" AndExpr } ;
AndExpr         = CmpExpr { "&&" CmpExpr } ;
CmpExpr         = BitOrExpr [ CmpOp BitOrExpr ] ;
CmpOp           = "==" | "!=" | "<" | ">" | "<=" | ">=" ;
BitOrExpr       = BitXorExpr { "|" BitXorExpr } ;
BitXorExpr      = BitAndExpr { "^" BitAndExpr } ;
BitAndExpr      = ShiftExpr { "&" ShiftExpr } ;
ShiftExpr       = AddExpr { ( "<<" | ">>" ) AddExpr } ;
AddExpr         = MulExpr { ( "+" | "-" ) MulExpr } ;
MulExpr         = CastExpr { ( "*" | "/" | "%" ) CastExpr } ;
CastExpr        = UnaryExpr { "as" Type } ;
UnaryExpr       = ( "-" | "!" | "~" | "&" ) UnaryExpr | NewExpr | PostfixExpr ;
NewExpr         = "new" Primary { PostfixOp } [ "?" { PostfixOp | "?" } ] ;
                                          (* The first "?" applies to the result of new *)
PostfixExpr     = Primary { PostfixOp | "?" } ;
PostfixOp       = "(" [ Args ] ")" | "[" Expr [ ".." Expr ] "]"
                | "." Ident | "->" Ident | ".*" ;
Args            = Expr { "," Expr } [ "," ] ;

Primary         = IntLit | FloatLit | CharLit | StringLit | WideStringLit
                | "true" | "false" | "null" | "self" | "original"
                | ExprPath [ StructLitBody ]
                | ArrayLit
                | "@" Ident "(" BuiltinArgs ")"
                | "(" Expr ")" ;
ExprPath        = [ "::" ] ExprSeg { "::" ExprSeg } ;
ExprSeg         = ( Ident | "Self" ) [ "::" "<" Type { "," Type } ">" ] ;
StructLitBody   = "{" [ FieldInit { "," FieldInit } [ "," ] ] "}" ;
FieldInit       = Ident ":" Expr ;
ArrayLit        = "[" ConstExpr "]" Type "{" [ Expr { "," Expr } [ "," ] ] "}" ;
BuiltinArgs     = ( Type | Expr ) { "," ( Type | Ident | Expr ) } ;

ConstExpr       = Expr ;                  (* Semantic analysis checks constness *)

Resolving syntactic ambiguities

  • In the header expression of if / while / for / match, a { immediately after an ExprPath is treated as the start of the body block, not as a struct literal. Enclose struct literals in parentheses.
  • The Block in OrElseRhs is chosen when { immediately follows orelse.
